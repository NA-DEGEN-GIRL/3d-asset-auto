# game-vfx 독립 세션 테스트

**한국어** | [English](VFX_TESTING.en.md)

스킬을 작성한 대화와 **별도의 새 LLM 세션**에서 실제 효과를 제작해 [game-vfx](../.agents/skills/game-vfx/SKILL.md)의 적용성을 확인합니다. 스킬 평가가 필요할 때 사용하는 안내이며, 일반 제작 요청마다 아래 보고 형식을 요구하지 않습니다.

## 새 세션에 줄 요청

시험할 스킬 버전을 고정하고 실제 프로젝트·참고 자료를 준비합니다. 작성 세션의 해결 코드, 정답 제작법, 기대 판정은 새 세션에 넘기지 않습니다. 아래 괄호는 사용자가 실제로 제공한 조건으로 채우고, 모르는 항목은 미정으로 둡니다. 특정 도구를 명시적으로 요청했다면 그 조건도 그대로 전달합니다.

```text
$game-vfx 이 프로젝트에서 [사용 상황과 효과 이름]을 만들어 줘.

프로젝트: [폴더, 알려진 엔진/렌더러·버전. 미정이면 미정]
효과: [시작·이동·충돌·종료 등 필요한 동작과 상호작용; 여러 개면 각각]
참고: [제공한 이미지·영상·기존 효과 경로와 채택할 특징]
사용 조건: [장치·카메라·크기·배경·동시 사용 조건 중 알려진 것]
품질 목표: [게임에서 읽혀야 하는 형태·시간·강약과 요구하는 완성도]
출력: [파일 형식과 저장 위치, 프로젝트 통합/미리보기 요청 여부]
허용 범위: [작업 시간·로컬 계산·저장 공간·유료 호출 및 비용 한도]

프로젝트와 연결된 스킬을 읽고, 제공한 조건에 맞게 제작해 줘.
여러 효과는 각각 제작·재생 검토·수정까지 진행해 줘.
편집 가능한 원본과 요청한 출력을 보존하고 실제 결과를 확인해 줘.
완료 후 결과 위치, 사용한 버전과 검사, 확인한 근거,
남은 결함과 검증하지 못한 조건을 간단히 보고해 줘.
이번 테스트에서는 스킬/공유 문서를 수정하거나 결과를 공개하지 마.
```

제작 방식은 명시된 요구와 실제 조건에서 선택하게 합니다. 엔진이 미정이어도 요청한 출력 형식은 지킵니다. 예산 항목은 기존 요청과 사용자가 이 테스트에서 정한 허용 범위를 기록하며, 그 범위를 넘어선 유료 호출·업로드를 허용하지 않습니다. 실행 결과·캐시·참고·캡처는 스킬 소스와 분리한 고유 로컬 폴더에 보존하고 기존 결과를 덮어쓰지 않습니다.

## 작성 세션에 돌려줄 근거

효과마다 짧게 기록합니다. 파일을 만들었거나 검사를 통과했다는 사실과 목표 품질을 달성했다는 판정을 구분합니다.

- 원래 요청, 스킬 버전/체크아웃, 실제 도구·렌더러 버전과 선택한 제작·재생 경로.
- 편집 가능한 원본, 전달 파일, 재현 진입점·명령, 수행한 검사와 로그 위치.
- 실제로 본 캡처/재생 근거와 사건 시각·카메라·사용 조건. 참고 이미지 자체를 최종 결과 근거로 쓰지 않습니다.
- 기준별 관찰, 수정 후 재검토, 남은 결함·미검증 범위와 예산/도구 차단 요인.

| 관찰한 원인 | 돌려줄 정보 |
| --- | --- |
| 지침이 없거나 모호함 | 어떤 결정에 안내가 부족했는지와 그 결과 |
| 지침은 있으나 적용하지 않음 | 해당 문구, 실제 행동과 차이 |
| 도구·환경·연동 문제 | 재현 명령, 버전, 오류와 가장 작은 실패 단계 |

여러 원인이 섞였거나 근거가 부족하면 그대로 표시합니다. 테스트 세션은 근거를 보고하고 스킬을 자동 수정하지 않습니다. 작성 세션은 관찰한 실패에서 재사용 가능한 판단 기준을 추려 수정합니다. 특정 샘플의 수치·모양을 고정한 정답이나 만점 평가표로 만들지 말고, 필요한 경우 다른 효과·프로젝트 조건의 새 세션에서 다시 확인합니다. 실제 제작·검토 기준은 [VFX 안내](VFX.md)를 따릅니다.
