# VFX 제작과 실험

**한국어** | [English](VFX.en.md)

게임 효과 제작은 별도 [game-vfx 스킬](../.agents/skills/game-vfx/SKILL.md)로 제공합니다. 기본 제작 도구는 Blender이며 절차적 필드·곡선·셰이더와 재사용 구성을 활용합니다. 별도의 물체 모델이 필요할 때 `3d-assets`를 연결하고, 모델이 필요 없는 효과에 TRELLIS나 Tripo를 요구하지 않습니다. 이 문서는 첫 구현과 이전 저작 실험을 함께 설명하며, [설계·실행 안내](GAME_VFX_DESIGN.md)에 설치·명령·라이선스 범위를 정리합니다.

## 현재 game-vfx 구현

| 구성 | 실제 역할과 경계 |
| --- | --- |
| [Blender 재료 도구](../.agents/skills/game-vfx/scripts/prepare_blender.py) | 반복 가능한 3D 노이즈와 번개 곡선·경로를 생성하고 `.blend`, 정적 경로 GLB, 설정·해시를 보존. 불·얼음 애니메이션 전체를 생성하는 명령은 아님 |
| [불 재생](../examples/game-vfx/effects.js) | Blender 노이즈를 샘플링하는 공간 화염 셰이더와 불씨. Mantaflow 유체 시뮬레이션이나 영상 평면 재생이 아님 |
| 얼음 재생 | 기존 TRELLIS 모델과 Blender 강체 베이크를 세 번의 시간차 낙하로 재사용. 임의 지형에 대한 실시간 파쇄·충돌은 아님 |
| 번개 재생 | Blender 경로를 굵기가 다른 입체 줄기·가지와 시간차 방전으로 표현. 물리적 전기 해석은 아님 |
| [웹 갤러리](../examples/game-vfx/preview.js) | 효과·시점·시간·크기·속도·배경·가림·겹침과 주효과/보조 층을 검토. 참고 이미지·영상은 비교 자료로 별도 표시 |

[실행 절차](GAME_VFX_DESIGN.md#불얼음번개-예제-실행)와 [정확한 데이터 계약](../.agents/skills/game-vfx/references/runtime.md)을 따릅니다. 전체 갤러리는 `noise.png`, `recipes.json`, `ice.glb`, `fire.png`, `ice.png`, `lightning.png`가 필요하며 효과별 MP4 참고 영상은 선택입니다. 생성 미디어는 Git에 포함하지 않습니다. 단일 불·번개 작업에 전체 갤러리의 얼음 모델이나 모든 예제 재생성을 요구하지 않습니다.

스킬에는 [효과별 제작·검토](../.agents/skills/game-vfx/references/workflow.md)를 분리했습니다. 시드·크기·속도와 구성 재사용을 지원하지만 색·동작·스타일의 큰 변경은 해당 저작/재생 코드를 수정해야 합니다. `asset_auto`의 범용 VFX 생성 CLI/MCP나 다른 엔진 자동 변환 기능은 없습니다. GLB만 요청했다면 지원되는 메시·재질·애니메이션 표현으로 설계하고, 웹의 화염 셰이더가 GLB에 포함된다고 설명하지 않습니다.

새 [웹 예제 소스](../examples/game-vfx/LICENSE.txt)는 MIT, Blender `bpy` 도구는 [GPL-3.0-or-later](../.agents/skills/game-vfx/scripts/COPYING.txt)입니다. 나머지 저장소·외부 모델·참고 미디어는 이 고지로 다시 라이선스하지 않습니다. 입력별 출처·이용 조건과 배포 의존성 고지를 보존합니다. 코드 제공이나 자동 검사 통과는 브라우저 시각 품질·성능 승인과 별개이며 결과별로 실제 검토합니다.

## 보존한 저작 실험

이전 실험은 **실제 3D 물체의 낙하·분리·파편 운동과 대상 렌더러용 효과 저작**을 다룹니다. 아래의 [낙하·파괴 예시](#낙하파괴-효과의-제작-예시)와 [소규모 기능 검사](#3d-파편의-물리-계산과-glb-검사)는 저작 가능한 범위와 확인한 범위를 구분합니다. 기존 `examples/vfx-web/`의 [충격파](../examples/vfx-web/effect.js)와 [불꽃 플립북](../examples/vfx-web/soul-effect.js)은 새 `examples/game-vfx/` 갤러리와 별개입니다. 기존 불꽃 플립북은 2D 표현 실험입니다.

## 현재 기능과 필요한 작업부터 확인하기

구현 전에 요청을 **공간상의 주형태, 움직임과 상태 전환, 주변과의 상호작용, 보조 효과, 전달 대상**으로 나눕니다. 각 부분이 기존 명령으로 되는지, 별도 저작이 필요한지, 추가 기능이 없는지를 확인하고 제작 경로와 미확인 범위를 설명합니다. `doctor`는 설치 상태를 찾는 출발점이며 효과 전체의 구현 가능성이나 품질을 증명하지 않습니다. 결과를 좌우하는 연결이 미확인이라면 작은 기능 검사부터 합니다.

| 단계 | 현재 지원과 경계 |
| --- | --- |
| 형태·시간 참고 | 사용 가능한 ImageGen·Grok 등으로 제작하거나 기존 자료 재사용. 이미지/영상은 설계 자료이며 3D 형상·입자·충돌 데이터로 자동 추출되지 않음 |
| 실제 덩어리 모델 | 참고 이미지 → TRELLIS.2 기본 생성, 명시적 Tripo 대안 또는 기존 메시 재사용. 얼음 재질과 내부 단면은 별도 마감 필요 |
| 파편 구성·낙하·물리 운동 | `blender-edit`의 신뢰된 Python으로 Blender 메시 편집·강체 계산·키프레임 저작 가능. 전용 파쇄 요청 스키마는 없고 GeoSAM의 의미 부품 분리는 파쇄가 아님 |
| 재생할 파일 | 계산한 파편 변환 → 공유 클립 → GLB는 아래 검사에서 확인. Blender 물리 캐시·충돌체·임의 셰이더가 GLB에 함께 전달되는 것은 아님 |
| 게임의 지형·충돌 사건 | 대상 프로젝트의 충돌 처리·파편 방출·수명 관리는 별도 구현과 검사 필요. 범용 어댑터는 없음 |

**입체 물체가 떨어져 부서지는 요청을 영상 한 장의 평면 재생으로 대체하지 않습니다.** Three.js 장면이나 회전 가능한 카메라 안에 있다는 사실만으로 내용이 3D가 되지 않습니다. 주형태의 깊이·회전·가림·접촉을 요구한 사용 범위에서 구현하고, 평면 입자나 플립북은 적합한 보조 층에 사용합니다. 시점 제한이 있는 표현을 선택했다면 그 조건을 밝힙니다.

## 표현 방식을 먼저 선택하기

효과의 목적, 대상 프로젝트/렌더러, 카메라 거리, 발생 위치·방향·크기, 준비·방출·소멸과 게임 사건의 대응을 정합니다. 짧은 타격 효과, 지속 오라, 이동 투사체에는 서로 다른 기준이 필요합니다. 엔진이 미정이면 이식 가능한 텍스처·메시·시간 명세 등 필요한 재료부터 준비하고, 명시적인 미리보기 요청 없이 웹앱이나 특정 엔진을 추가하지 않습니다.

| 필요한 표현 | 제작·전달 방식 |
| --- | --- |
| 파편·물체의 이동, 변형되는 효과 메시 | Blender object/morph/rig 동작과 GLB; 최종 대상에서 재생 확인 |
| 불티·연기·폭발의 반복 입자 | 대상 엔진의 파티클/스프라이트 시스템, 방출·수명·난수·재질 설정 |
| 충격파·베기 궤적·마법진·왜곡 | 셰이더, 리본/트레일 또는 효과 표면, 재질·시간·방향 설정 |
| 그린 불꽃·연무 등 복잡한 표면 변화 | 필요에 따라 생성 이미지, 시뮬레이션 또는 수작업 이미지에서 검토한 텍스처/플립북 |

VFX 요청에는 효과를 그리는 점·쿼드·링·리본과 셰이더를 작성하는 작업이 포함됩니다. 이 렌더링용 표면에 TRELLIS나 리그를 억지로 적용하지 않습니다. **얼음 덩어리·운석·무기·건물 같은 실제 모델의 새 생성은 기존 TRELLIS 기본 원칙을 따릅니다.** 기존 메시에서 파편을 자르고 단면을 만드는 것은 편집이며 재생성이 필요하지 않습니다. Tripo와 Kimodo의 명시적 선택 조건도 그대로입니다.

GLB는 재사용할 메시와 지원되는 애니메이션을 전달하는 수단입니다. 임의의 셰이더, 방출기, 화면 왜곡, 후처리, 게임 이벤트 로직까지 GLB 하나로 보존된다고 가정하지 않습니다. 네이티브 효과는 코드/셰이더/텍스처와 설정을 함께 전달합니다. 엔진별 의미가 다른 기능은 따로 구현하고 검사합니다. Godot와 Three.js 양쪽 검증을 일괄 의무화하지 않습니다.

## 질감과 흐름이 핵심인 효과

불·물·얼음·영혼처럼 형태, 표면과 시간 변화가 품질을 좌우하는 요청을 색만 바꾼 기본 입자나 도형으로 대체하지 않습니다. 충분한 기존 자료를 재사용하거나 **초기 설계에서 필요한 이미지와 시간 자료를 준비**하고, 채택할 실루엣·질감·변화 방향·방출 속도·잔광 등의 목표를 정합니다. 단순한 범위 표시나 의도된 기하 효과에는 새 이미지/영상 생성을 일괄 강제하지 않습니다.

- **이미지:** ImageGen 등으로 표현을 설계하거나 실제 사용할 텍스처를 만듭니다. 참고 그림과 런타임 텍스처를 구분하고, 텍스처로 사용할 때는 투명도·여백·경계·반복 가능성을 검사합니다. 불꽃 그림 한 장을 흔드는 것만으로 새 불길이 생기고 갈라지는 동작을 재현했다고 하지 않습니다.
- **영상:** Grok 등의 자료에서 시작·최대 표현·사라짐과 그 사이의 흐름을 채택합니다. [Grok 작업·복구 지침](MOTION_REFERENCES.md#grok-build-headless-사용)을 따릅니다. 3D 물체에는 사건 시각·궤적·회전·속도 변화의 참고로 적용합니다. 플립북은 선택한 층에 평면 표현이 적합할 때만 검토하며, 카메라·크기·배경과 프레임 일관성을 확인합니다. 생성한 다중 패널 이미지를 시간적으로 일관된 프레임 시퀀스로 간주하지 않습니다.
- **구현 선택:** 시점이 제한된 불꽃·연무에는 플립북이 유용할 수 있습니다. 자유로운 시점의 부피, 수면 굴절·교차, 입체적인 궤적과 충돌이 필요하면 Blender 시뮬레이션/메시나 대상 엔진의 깊이·노멀·파티클/셰이더 기능을 조합합니다. 영상에서 3D 흐름·깊이·노멀이 자동으로 복원된다고 가정하지 않습니다.
- **합성:** 핵심 형태, 세부 입자, 궤적, 접지 표현, 잔광 중 요청에 필요한 층을 선택합니다. 층을 많이 추가하는 것보다 서로 다른 발생 시점·수명과 주효과의 가독성을 맞추는 것이 중요합니다. 카메라 흔들림·빛·음향·피해 판정은 별도 통합 요소이며 요청과 대상에 맞을 때만 추가합니다.

플립북은 프레임 순서·FPS·원본 시각·행렬 배치·텍셀 경계·알파/색공간·메모리 비용을 보존하고 확인합니다. 끝에서 처음으로 돌아간다고 자연스러운 루프가 되는 것은 아닙니다. 검은 배경의 발광 영상을 밝기 기반으로 합성하는 방법은 **이 샘플의 근사 처리**이며, 물·불투명 연기·검은 재질에 그대로 적용하지 않습니다. 그 경우 별도의 알파/마스크나 다른 제작 방식을 선택합니다.

상용 ARPG 수준을 목표로 할 때도 특정 게임의 제작 도구를 사용했다는 사실이 품질을 보장하지 않습니다. 목표 시점에서 참고와 최종 효과의 형태·시간·강약을 대응시켜 비교하고, 실제 전투 배경·동시 발동·예산에서 수정합니다. **생성 참고의 완성도를 구현 결과의 완성도로 보고하지 않습니다.**

## 낙하·파괴 효과의 제작 예시

얼음 덩어리가 내려와 바닥에서 깨지는 경우의 경로입니다. 운석·바위·소품 파괴에도 필요한 판단을 재사용하되 파편 수, 속도, 재질이나 제작 방식을 고정하지 않습니다.

1. **참고를 제작 목표로 옮깁니다.** 이미지에서 덩어리의 실루엣·두께·얼음 표면과 내부를, 영상에서 낙하 순서·가속·충돌·파편 확산·잔류 시간을 채택합니다. 사건별 시각과 목표를 기록하고 실제 구현에서 대응시킵니다. 생성 영상의 물체 소실, 불가능한 충돌이나 일관되지 않은 파편은 제외합니다. 충분한 자료는 재사용하며 모든 파편마다 새 생성을 요구하지 않습니다.
2. **원본 메시에서 파편을 준비합니다.** 생성하거나 제공받은 덩어리를 보존하고 Blender에서 절단·단면 채우기 등 적절한 방법을 선택합니다. 외부 표면과 내부 단면의 재질, 조각의 닫힘·겹침, 원점과 충돌 형상을 확인합니다. 복잡한 파쇄에 확장 기능을 쓰려면 실제 설치·호환성과 호출을 먼저 검증합니다. 아래 검사는 기본 메시 연산을 썼으며 Cell Fracture 설치를 전제하지 않습니다.
3. **재생 방식과 파괴 사건을 정합니다.** 정해진 표면에서 반복할 연출은 사전 계산한 애니메이션으로 전달할 수 있습니다. 임의 지형·이동 표적에 반응해야 한다면 게임에서 충돌을 감지하고 파편 상태로 전환하는 코드가 필요합니다. 정해진 시각에 깨지는 클립을 실행 중 충돌에 반응하는 효과라고 하지 않습니다. 단단한 덩어리·파편에는 물체 변환을 사용하며 인간형 리그나 Kimodo가 필요하지 않습니다.
4. **낙하에서 파편 운동까지 연결합니다.** 조립된 파편을 충돌 시점에 풀거나, 온전한 모델을 위치·자세가 맞는 파편으로 교체합니다. 전환 시 위치 튐, 이중 표시, 남아 있는 원본을 검사합니다. 파편 궤적은 저작하거나 강체로 계산한 뒤 표현 목표에 맞게 조정합니다. 발동 후 재생용 GLB에는 평가된 위치·회전을 베이크하여 모든 조각이 공유 시간축의 한 클립에서 움직이게 합니다. `hide_render`, 물리 캐시나 재질 노드 키프레임이 그대로 내보내진다고 가정하지 말고, 지원되는 변환 또는 검증한 엔진 사건을 선택합니다. 시뮬레이션 원본과 베이크한 원본을 함께 보존합니다.
5. **대상 재질과 보조 효과를 합칩니다.** 얼음의 투과·굴절·거칠기는 실제 대상에서 확인합니다. Blender 렌더와 같은 표현을 GLB 재질만으로 보장하지 않습니다. 충돌 순간의 서리·가루·잔광은 입자·플립북으로 보완할 수 있지만 주역인 덩어리와 파편의 3D 움직임을 대신하지 않습니다. 엔진이 미정이면 메시·베이크 클립·참고와 사건 명세를 전달하고, 특정 엔진 통합은 미검증으로 남깁니다.
6. **사건별로 비교하고 고칩니다.** 낙하, 첫 접촉, 분리, 확산, 정착을 참고와 최종 재생에서 대응시킵니다. 같은 순간을 사용 카메라와 측면·후면·위쪽 중 결함을 드러내는 방향에서 살핍니다. 파편의 원래 덩어리와의 대응, 깊이와 가림, 바닥 관통·공중 정지, 타격감, 잔류·종료를 확인합니다. 요구한 사용 조건에서 재발동·취소·동시 사용도 검사합니다. 기술적으로 내보내졌어도 채택한 형태·속도·파괴 표현이 부족하면 미완료입니다.

### 3D 파편의 물리 계산과 GLB 검사

유지보수용 [smoke_vfx_rigidbody.py](../scripts/smoke_vfx_rigidbody.py)는 설치된 Blender와 기존 GLB 내보내기 경로를 사용합니다. 모델 추론·유료 호출·웹앱은 필요하지 않으며 모든 에셋 작업에 의무 실행하는 검사가 아닙니다.

```sh
uv run --no-sync python scripts/smoke_vfx_rigidbody.py
```

소규모 절차적 검사 메시를 닫힌 조각으로 절단하고, 저작한 낙하·방출 뒤의 강체 운동을 계산합니다. 평가된 변환을 공유 Blender Action에 베이크하여 한 GLB 클립으로 내보내고, 다시 가져온 파편의 여러 시점 변환을 원래 계산과 비교합니다. 분할 전후 부피, 닫힌 조각, 방출 후 운동과 바닥 관통의 제한도 확인합니다. 결과는 `.work/smoke-vfx-rigidbody-*/`의 `report.json`, `simulation.blend`, `baked.blend`, `asset.glb`에 남습니다.

이 검사가 증명하는 것은 **메시 절단 → 강체 계산 → 한 클립 베이크 → GLB 변환 보존**입니다. 충격/응력에 따른 자동 파쇄, 생성 얼음의 품질·재질·자연스러움, 전체 CLI 리비전 절차, 엔진의 충돌·피해·수명 처리는 검사하지 않습니다. 검사 메시를 실제 생성 에셋이나 완성된 스킬 효과로 보고하지 않습니다.

## 설계·제작·검토

1. **관찰할 목표를 정합니다.** 시작 신호가 읽히는지, 최대 확산과 방향이 의도에 맞는지, 타격/방출 시점이 맞는지, 끝에 잔상이 남는지 등 용도에 맞는 몇 가지를 선택합니다. 여러 효과는 개별로 추적합니다. 어려운·창의적인 효과는 초기부터 [이미지·시간 참고](MOTION_REFERENCES.md)를 검토합니다. 생성 영상은 표현 참고이며 알파가 있는 텍스처나 실제 입자 자료라고 간주하지 않습니다.
2. **층과 시간을 나눠 작성합니다.** 준비, 핵심 사건, 잔광 등의 시간을 초 단위로 기록합니다. 게임 사건과 시각 사건을 구분하며 충돌·피해 판정은 시각 효과만으로 구현됐다고 하지 않습니다. 반복·한 번 재생, 로컬/월드 공간, 부착·이동, 중단·재시작 정책을 정합니다. 참고의 크기·실루엣·속도 변화를 보존하고, 결함을 숨기려고 표현을 무조건 줄이지 않습니다.
3. **실제 대상에서 재생합니다.** 중요한 동일 시점과 전환을 사용 카메라·필요한 다른 각도, 밝고 어두운 배경, 실제 크기에서 확인합니다. 투명 사각 테두리, 잘못된 정렬, 교차면, 깊이 가림, 플립북 이음, 의도하지 않은 점멸과 갑작스러운 소멸을 살핍니다. 얇은 바닥 효과가 옆에서 좁아지는 것은 표현의 특성이며 모든 방향에서 같은 모양을 강제하지 않습니다.
4. **수명과 비용을 검사합니다.** 반복 발동, 중단, 시간 이동이 있다면 역방향 탐색, 동시에 여러 인스턴스 사용, 자원 해제와 범위를 확인합니다. 대상 해상도·장치에서 입자 수, 투명 영역의 겹침과 draw call/프레임 비용 중 필요한 항목을 측정합니다. 작은 샘플의 draw call 수로 모바일 성능이나 대규모 전투 성능을 보증하지 않습니다.
5. **같은 조건에서 수정·재검토합니다.** [품질 원칙](QUALITY.md)에 따라 결함·시점·시점 방향·수정과 남은 문제를 기록합니다. 수치 검사, 실제 시각 검토, 게임 사건 통합을 별도로 판정합니다. 셰이더 컴파일이나 서버 응답 성공만으로 효과를 승인하지 않습니다. 유료 참고/생성은 기존 승인 범위 안에서만 사용합니다.

최종 전달에는 효과 원본과 의존성 버전, 진입점, 좌표·크기, 재생/종료 방법, 사건 시간, 난수 정책, 대상과 검토 범위를 포함합니다. 자동 실행되지 않는 장면이나 출처를 알 수 없는 텍스처를 결과로 넘기지 않습니다. 생성 결과·검토 캡처는 기본적으로 로컬에 보존합니다.

## Three.js 소규모 웹 테스트

저장소 루트에서 실행합니다. 기존 웹 의존성이 설치되어 있으면 `npm ci`는 생략합니다. 모델 다운로드·Blender·Godot·유료 API가 필요하지 않습니다.

```sh
npm --prefix web ci
node examples/vfx-web/build.mjs
uv run --no-sync python -m http.server 8775 --bind 127.0.0.1 --directory .work/vfx-web/site
```

[로컬 미리보기](http://127.0.0.1:8775/)를 엽니다. 서버를 실행한 터미널은 열어 두고 종료할 때 Ctrl+C를 누릅니다. 기존 GLB 라이브러리 뷰어와 별개이며 이 디렉터리의 정적 파일만 제공합니다. 포트가 사용 중이면 다른 빈 포트를 선택합니다.

이 예제는 응축 → 방출 → 확산 → 소멸의 **2.4초 마법 충격파**입니다. 재생/일시정지, 속도, 시간 이동, 핵심 시점 버튼, 사선·측면·위 카메라, 두 배경, 층별 표시, 가림 물체와 지연된 두 번째 효과를 지원합니다. `prefers-reduced-motion` 사용자는 정지 화면에서 시작합니다. 원본은 `examples/vfx-web/`, 번들은 Git에 포함되지 않는 `.work/vfx-web/site/`에 있습니다. 미리보기 실행 중에는 CDN이나 원격 생성 서비스에 연결하지 않습니다.

### 프로젝트에서 재사용

프로젝트가 쓰는 Three.js 번들러에 `effect.js`를 가져옵니다. 이 저장소에서 검증할 버전은 `web/package-lock.json`을 따릅니다.

```js
import { createArcanePulse } from './effect.js';

const pulse = createArcanePulse({ seed: 17, color: '#57eadb' });
scene.add(pulse.group);
pulse.group.position.set(0, 0, 0);
// 매 프레임: 발동 시점부터 경과한 초. 0과 duration 이상에서는 숨겨집니다.
pulse.update(elapsedSeconds);
// 중단/풀 반환: 숨기고, 다음 발동에서 시간을 0부터 다시 전달합니다.
pulse.update(0);
// 영구 제거: 장면에서 분리하고 이 인스턴스가 가진 GPU 자원을 해제합니다.
pulse.dispose();
```

Three.js **Y-up**, 바닥 XZ, 예제 크기는 월드 단위이며 기본 외곽 파동 반경은 약 3.5입니다. `group`의 변환으로 배치합니다. 각 인스턴스는 자신의 재질과 난수를 소유하며 절대 경과 시간으로 갱신하므로 앞뒤 탐색이 가능합니다. 발동 기준 사건 시간은 `pulse.impact`(0.46초)입니다. 이는 시각 설계 정보이고 `update()`가 게임 콜백을 발행하지는 않습니다. 게임은 일시정지·탐색·다시 발동 때 사건을 처리할 정책을 따로 정해야 합니다.

### 이미지·영상 기반 영혼 불꽃

이 예제는 **2D 플립북 표현 실험**입니다. 입체 불꽃이나 자유 시점의 3D 효과를 완성했다는 증거로 사용하지 않습니다.

로컬 테스트에서는 내장 ImageGen으로 투명한 영혼 불꽃 이미지 1장을 만들고, Grok `image_to_video` 1회로 6초 참고 영상을 생성했습니다. 관찰한 영상은 544×544, 24 FPS, 145프레임이고, 검토한 개요 프레임에서는 청록색 불길·보라색 외곽·갈라지는 형태가 유지됩니다. 이를 16 FPS의 96프레임, 각 256×256인 8열×12행 PNG로 변환했습니다. 이 수치는 샘플 선택이며 공통 품질 기준이 아닙니다. 원본과 생성 프롬프트는 `.work/vfx-soul/reference/`에 보존하며 Git에 올리지 않습니다.

동일한 파일 계약의 로컬 자료가 있을 때:

```sh
ffmpeg -hide_banner -loglevel error -n -i .work/vfx-soul/reference/soul-flame.mp4 -vf "fps=16,scale=256:256,tile=8x12" -frames:v 1 .work/vfx-soul/reference/soul-atlas.png
node examples/vfx-web/build.mjs --media-dir .work/vfx-soul/reference
```

폴더에 `soul-flame.png`, `soul-flame.mp4`, `soul-atlas.png`가 모두 필요합니다. 예제용 `--media-dir`은 이 파일 세 개만 복사하고, 위 배치·프레임 수·FPS를 설정합니다. 다른 규격은 설정과 코드를 함께 맞춥니다. 새 checkout에는 생성 미디어가 없으므로 기본 도형 샘플부터 열립니다. **미디어 없는 기본 예제를 실행한 것은 이미지/영상 기반 제작의 증거가 아닙니다.**

새로고침하면 영혼 불꽃을 먼저 표시하며 아래에서 기준 이미지·원본 영상을 볼 수 있습니다. 효과 선택으로 도형 충격파와 전환합니다. 런타임은 프레임 보간·등장/종료 페이드·검은 배경 제거와 바닥 잔광을 더하며, 실제 3D 볼륨이나 유체 해석이 아닙니다. 카메라를 향하는 평면의 깊이·가림·교차 한계가 있습니다. 디코딩된 아틀라스의 GPU RGBA8 기준 크기는 약 24 MiB이고 mipmap은 사용하지 않습니다. 파일의 압축 크기와 GPU 비용은 다릅니다.

`createSoulFlame({ texture, columns, rows, frames, fps })`는 `group`, `duration`, `update(seconds)`, `setLayer(name, visible)`, `dispose()`를 제공합니다. 층 이름은 `body`와 `halo`입니다. 텍스처는 호출자가 소유하여 마지막 인스턴스 제거 후 따로 `dispose()`합니다. 프레임 선택은 역방향 탐색이 가능하며 마지막 프레임에서 멈춥니다. 이 예제의 UI 반복은 효과 재발동이고 연속 불꽃 루프는 아닙니다.

### 생성 메시를 사용하는 얼음 낙하 예제

`ice-effect.js`는 실제 GLB의 이름 있는 클립을 재생하며, 독립된 두 인스턴스·역방향 시간 이동·최종 파편 유지와 서리 입자를 지원합니다. 참조 영상은 비교 자료이고 주효과는 입체 메시입니다. 로컬 제작에서는 ImageGen 형태 → TRELLIS.2 → 원본 표면 복구·파편 절단 → Blender 강체 계산·베이크를 사용했고, 내부 단면에는 별도로 생성한 얼음 텍스처를 적용했습니다. 단면의 Three.js 재질 보정은 GLB 재질과 별도입니다.

생성 결과는 Git에 포함되지 않습니다. 로컬 폴더에 `ice.glb`, `ice.png`, `ice.mp4`, `ice-events.json`을 준비한 뒤 연결합니다. 사건 파일은 `clip`, 양수 `duration`, 클립 안의 `impact`, 타임라인 버튼용 시각 네 개의 `moments`, 표시용 `fragments`를 포함합니다. 필요하면 `start_offset`에 GLB의 시작 시각을 지정합니다. 이 예제의 Blender 24 FPS 클립은 `1/24`초이며 모든 사건·버튼 시각은 그 시작점부터 잽니다.

```sh
node examples/vfx-web/build.mjs --ice-dir .work/vfx-ice/delivery
```

기존 불꽃 자료도 유지하려면 같은 명령에 `--media-dir .work/vfx-soul/reference`를 추가합니다. 서버는 위와 같은 `.work/vfx-web/site/`를 제공합니다. 조립·분리·확산·정착을 같은 시각의 여러 방향에서 비교하고, 입자를 꺼 메시 자체도 검사합니다. 충돌 시점이 고정된 재생 예제이며 임의 지형에 반응하는 실시간 파쇄가 아닙니다. 상용 게임 품질이나 다수 동시 효과의 성능을 보증하지 않습니다.

### 작은 자동 검사와 한계

얼음 재생 검사는 클립 종료 후 역방향 탐색, 정착한 조각 유지, 인스턴스 독립성과 공유 GLB 자원의 소유권도 확인합니다.

```sh
node examples/vfx-web/build.mjs --test
node .work/vfx-web/effect.test.cjs
```

검사는 역방향 탐색의 재현성, 시드·재질·층 설정의 인스턴스 독립성, 유효한 입자 좌표, 시작/종료/재시작, 반복 생성 후 자원 해제 사건과 플립북 보간·텍스처 소유권을 확인합니다. **GPU 메모리 측정이나 실제 화면·성능 승인을 대신하지 않습니다.** 브라우저에서 핵심 시점·전환·배경·가림·겹침을 따로 확인해야 합니다. 이 예제에는 유체 시뮬레이션, soft particle 교차면 처리, 충돌·피해 로직, 엔진 간 변환이 포함되지 않습니다. 미디어 생성은 사용 가능한 외부 도구로 수행하며 예제 빌드 자체가 생성 서비스를 호출하지 않습니다.
