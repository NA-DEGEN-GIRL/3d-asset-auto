# 게임 효과와 VFX

**한국어** | [English](VFX.en.md)

스킬은 메시 에셋과 별도로 **대상 렌더러에 맞춘 게임 효과를 작성·검토**할 수 있습니다. 현재 제공하는 시작점은 [Three.js 충격파](../examples/vfx-web/effect.js)와 [이미지·영상 기반 불꽃 플립북](../examples/vfx-web/soul-effect.js) 예제입니다. 범용 VFX 생성 모델, 영상→3D 입자 추출, Blender 효과를 모든 엔진으로 옮기는 자동 변환기는 구현되어 있지 않습니다.

## 표현 방식을 먼저 선택하기

효과의 목적, 대상 프로젝트/렌더러, 카메라 거리, 발생 위치·방향·크기, 준비·방출·소멸과 게임 사건의 대응을 정합니다. 짧은 타격 효과, 지속 오라, 이동 투사체에는 서로 다른 기준이 필요합니다. 엔진이 미정이면 이식 가능한 텍스처·메시·시간 명세 등 필요한 재료부터 준비하고, 명시적인 미리보기 요청 없이 웹앱이나 특정 엔진을 추가하지 않습니다.

| 필요한 표현 | 제작·전달 방식 |
| --- | --- |
| 파편·물체의 이동, 변형되는 효과 메시 | Blender object/morph/rig 동작과 GLB; 최종 대상에서 재생 확인 |
| 불티·연기·폭발의 반복 입자 | 대상 엔진의 파티클/스프라이트 시스템, 방출·수명·난수·재질 설정 |
| 충격파·베기 궤적·마법진·왜곡 | 셰이더, 리본/트레일 또는 효과 표면, 재질·시간·방향 설정 |
| 그린 불꽃·연무 등 복잡한 표면 변화 | 필요에 따라 생성 이미지, 시뮬레이션 또는 수작업 이미지에서 검토한 텍스처/플립북 |

VFX 요청에는 효과를 그리는 점·쿼드·링·리본과 셰이더를 작성하는 작업이 포함됩니다. 이 렌더링용 표면에 TRELLIS나 리그를 억지로 적용하지 않습니다. **함께 필요한 실제 무기·건물·장식 모델의 새 생성은 기존 TRELLIS 기본 원칙을 따릅니다.** Tripo와 Kimodo의 명시적 선택 조건도 그대로입니다.

GLB는 재사용할 메시와 지원되는 애니메이션을 전달하는 수단입니다. 임의의 셰이더, 방출기, 화면 왜곡, 후처리, 게임 이벤트 로직까지 GLB 하나로 보존된다고 가정하지 않습니다. 네이티브 효과는 코드/셰이더/텍스처와 설정을 함께 전달합니다. 엔진별 의미가 다른 기능은 따로 구현하고 검사합니다. Godot와 Three.js 양쪽 검증을 일괄 의무화하지 않습니다.

## 질감과 흐름이 핵심인 효과

불·물·얼음·영혼처럼 형태, 표면과 시간 변화가 품질을 좌우하는 요청을 색만 바꾼 기본 입자나 도형으로 대체하지 않습니다. 충분한 기존 자료를 재사용하거나 **초기 설계에서 필요한 이미지와 시간 자료를 준비**하고, 채택할 실루엣·질감·변화 방향·방출 속도·잔광 등의 목표를 정합니다. 단순한 범위 표시나 의도된 기하 효과에는 새 이미지/영상 생성을 일괄 강제하지 않습니다.

- **이미지:** ImageGen 등으로 표현을 설계하거나 실제 사용할 텍스처를 만듭니다. 참고 그림과 런타임 텍스처를 구분하고, 텍스처로 사용할 때는 투명도·여백·경계·반복 가능성을 검사합니다. 불꽃 그림 한 장을 흔드는 것만으로 새 불길이 생기고 갈라지는 동작을 재현했다고 하지 않습니다.
- **영상:** Grok 등의 자료에서 시작·최대 표현·사라짐과 그 사이의 흐름을 채택합니다. [Grok 작업·복구 지침](MOTION_REFERENCES.md#grok-build-headless-사용)을 따릅니다. 카메라와 크기, 배경이 안정적이고 의도한 형태 변화가 있는 영상은 실제 프레임을 플립북으로 베이크하는 후보가 됩니다. 생성한 다중 패널 이미지를 시간적으로 일관된 프레임 시퀀스로 간주하지 않습니다.
- **구현 선택:** 시점이 제한된 불꽃·연무에는 플립북이 유용할 수 있습니다. 자유로운 시점의 부피, 수면 굴절·교차, 입체적인 궤적과 충돌이 필요하면 Blender 시뮬레이션/메시나 대상 엔진의 깊이·노멀·파티클/셰이더 기능을 조합합니다. 영상에서 3D 흐름·깊이·노멀이 자동으로 복원된다고 가정하지 않습니다.
- **합성:** 핵심 형태, 세부 입자, 궤적, 접지 표현, 잔광 중 요청에 필요한 층을 선택합니다. 층을 많이 추가하는 것보다 서로 다른 발생 시점·수명과 주효과의 가독성을 맞추는 것이 중요합니다. 카메라 흔들림·빛·음향·피해 판정은 별도 통합 요소이며 요청과 대상에 맞을 때만 추가합니다.

플립북은 프레임 순서·FPS·원본 시각·행렬 배치·텍셀 경계·알파/색공간·메모리 비용을 보존하고 확인합니다. 끝에서 처음으로 돌아간다고 자연스러운 루프가 되는 것은 아닙니다. 검은 배경의 발광 영상을 밝기 기반으로 합성하는 방법은 **이 샘플의 근사 처리**이며, 물·불투명 연기·검은 재질에 그대로 적용하지 않습니다. 그 경우 별도의 알파/마스크나 다른 제작 방식을 선택합니다.

상용 ARPG 수준을 목표로 할 때도 특정 게임의 제작 도구를 사용했다는 사실이 품질을 보장하지 않습니다. 목표 시점에서 참고와 최종 효과의 형태·시간·강약을 대응시켜 비교하고, 실제 전투 배경·동시 발동·예산에서 수정합니다. **생성 참고의 완성도를 구현 결과의 완성도로 보고하지 않습니다.**

## 설계·제작·검토

1. **관찰할 목표를 정합니다.** 시작 신호가 읽히는지, 최대 확산과 방향이 의도에 맞는지, 타격/방출 시점이 맞는지, 끝에 잔상이 남는지 등 용도에 맞는 몇 가지를 선택합니다. 여러 효과는 개별로 추적합니다. 어려운·창의적인 효과는 초기부터 [이미지·시간 참고](MOTION_REFERENCES.md)를 검토합니다. 생성 영상은 표현 참고이며 알파가 있는 텍스처나 실제 입자 자료라고 간주하지 않습니다.
2. **층과 시간을 나눠 작성합니다.** 준비, 핵심 사건, 잔광 등의 시간을 초 단위로 기록합니다. 게임 사건과 시각 사건을 구분하며 충돌·피해 판정은 시각 효과만으로 구현됐다고 하지 않습니다. 반복·한 번 재생, 로컬/월드 공간, 부착·이동, 중단·재시작 정책을 정합니다. 참고의 크기·실루엣·속도 변화를 보존하고, 결함을 숨기려고 표현을 무조건 줄이지 않습니다.
3. **실제 대상에서 재생합니다.** 중요한 동일 시점과 전환을 사용 카메라·필요한 다른 각도, 밝고 어두운 배경, 실제 크기에서 확인합니다. 투명 사각 테두리, 잘못된 정렬, 교차면, 깊이 가림, 플립북 이음, 의도하지 않은 점멸과 갑작스러운 소멸을 살핍니다. 얇은 바닥 효과가 옆에서 좁아지는 것은 표현의 특성이며 모든 방향에서 같은 모양을 강제하지 않습니다.
4. **수명과 비용을 검사합니다.** 반복 발동, 중단, 시간 이동이 있다면 역방향 탐색, 동시에 여러 인스턴스 사용, 자원 해제와 범위를 확인합니다. 대상 해상도·장치에서 입자 수, 투명 영역의 겹침과 draw call/프레임 비용 중 필요한 항목을 측정합니다. 작은 샘플의 draw call 수로 모바일 성능이나 대규모 전투 성능을 보증하지 않습니다.
5. **같은 조건에서 수정·재검토합니다.** [품질 원칙](QUALITY.md)에 따라 결함·시점·시점 방향·수정과 남은 문제를 기록합니다. 수치 검사, 실제 시각 검토, 게임 사건 통합을 별도로 판정합니다. 셰이더 컴파일이나 서버 응답 성공만으로 효과를 승인하지 않습니다. 유료 참고/생성은 기존 승인 범위 안에서만 사용합니다.

최종 전달에는 효과 원본과 의존성 버전, 진입점, 좌표·크기, 재생/종료 방법, 사건 시간, 난수 정책, 대상과 검토 범위를 포함합니다. 자동 실행되지 않는 장면이나 출처를 알 수 없는 텍스처를 결과로 넘기지 않습니다. 생성 결과·검토 캡처는 기본적으로 로컬에 보존합니다.

## Three.js 소규모 웹 테스트

저장소 루트에서 실행합니다. 기존 웹 의존성이 설치되어 있으면 `npm ci`는 생략합니다. 모델 다운로드·Blender·Godot·유료 API가 필요하지 않습니다.

```sh
npm --prefix web ci
node examples/vfx-web/build.mjs
uv run --no-sync python -m http.server 8775 --bind 127.0.0.1 --directory .work/vfx-web/site
```

[로컬 미리보기](http://127.0.0.1:8775/)를 엽니다. 서버를 실행한 터미널은 열어 두고 종료할 때 Ctrl+C를 누릅니다. 기존 GLB 라이브러리 뷰어와 별개이며 이 디렉터리의 정적 파일만 제공합니다. 포트가 사용 중이면 다른 빈 포트를 선택합니다.

이 예제는 응축 → 방출 → 확산 → 소멸의 **2.4초 마법 충격파**입니다. 재생/일시정지, 속도, 시간 이동, 핵심 시점 버튼, 사선·측면·위 카메라, 두 배경, 층별 표시, 가림 물체와 지연된 두 번째 효과를 지원합니다. `prefers-reduced-motion` 사용자는 정지 화면에서 시작합니다. 원본은 `examples/vfx-web/`, 번들은 Git에 포함되지 않는 `.work/vfx-web/site/`에 있습니다. 미리보기 실행 중에는 CDN이나 원격 생성 서비스에 연결하지 않습니다.

### 프로젝트에서 재사용

프로젝트가 쓰는 Three.js 번들러에 `effect.js`를 가져옵니다. 이 저장소에서 검증할 버전은 `web/package-lock.json`을 따릅니다.

```js
import { createArcanePulse } from './effect.js';

const pulse = createArcanePulse({ seed: 17, color: '#57eadb' });
scene.add(pulse.group);
pulse.group.position.set(0, 0, 0);
// 매 프레임: 발동 시점부터 경과한 초. 0과 duration 이상에서는 숨겨집니다.
pulse.update(elapsedSeconds);
// 중단/풀 반환: 숨기고, 다음 발동에서 시간을 0부터 다시 전달합니다.
pulse.update(0);
// 영구 제거: 장면에서 분리하고 이 인스턴스가 가진 GPU 자원을 해제합니다.
pulse.dispose();
```

Three.js **Y-up**, 바닥 XZ, 예제 크기는 월드 단위이며 기본 외곽 파동 반경은 약 3.5입니다. `group`의 변환으로 배치합니다. 각 인스턴스는 자신의 재질과 난수를 소유하며 절대 경과 시간으로 갱신하므로 앞뒤 탐색이 가능합니다. 발동 기준 사건 시간은 `pulse.impact`(0.46초)입니다. 이는 시각 설계 정보이고 `update()`가 게임 콜백을 발행하지는 않습니다. 게임은 일시정지·탐색·다시 발동 때 사건을 처리할 정책을 따로 정해야 합니다.

### 이미지·영상 기반 영혼 불꽃

로컬 테스트에서는 내장 ImageGen으로 투명한 영혼 불꽃 이미지 1장을 만들고, Grok `image_to_video` 1회로 6초 참고 영상을 생성했습니다. 관찰한 영상은 544×544, 24 FPS, 145프레임이고, 검토한 개요 프레임에서는 청록색 불길·보라색 외곽·갈라지는 형태가 유지됩니다. 이를 16 FPS의 96프레임, 각 256×256인 8열×12행 PNG로 변환했습니다. 이 수치는 샘플 선택이며 공통 품질 기준이 아닙니다. 원본과 생성 프롬프트는 `.work/vfx-soul/reference/`에 보존하며 Git에 올리지 않습니다.

동일한 파일 계약의 로컬 자료가 있을 때:

```sh
ffmpeg -hide_banner -loglevel error -n -i .work/vfx-soul/reference/soul-flame.mp4 -vf "fps=16,scale=256:256,tile=8x12" -frames:v 1 .work/vfx-soul/reference/soul-atlas.png
node examples/vfx-web/build.mjs --media-dir .work/vfx-soul/reference
```

폴더에 `soul-flame.png`, `soul-flame.mp4`, `soul-atlas.png`가 모두 필요합니다. 예제용 `--media-dir`은 이 파일 세 개만 복사하고, 위 배치·프레임 수·FPS를 설정합니다. 다른 규격은 설정과 코드를 함께 맞춥니다. 새 checkout에는 생성 미디어가 없으므로 기본 도형 샘플부터 열립니다. **미디어 없는 기본 예제를 실행한 것은 이미지/영상 기반 제작의 증거가 아닙니다.**

새로고침하면 영혼 불꽃을 먼저 표시하며 아래에서 기준 이미지·원본 영상을 볼 수 있습니다. 효과 선택으로 도형 충격파와 전환합니다. 런타임은 프레임 보간·등장/종료 페이드·검은 배경 제거와 바닥 잔광을 더하며, 실제 3D 볼륨이나 유체 해석이 아닙니다. 카메라를 향하는 평면의 깊이·가림·교차 한계가 있습니다. 디코딩된 아틀라스의 GPU RGBA8 기준 크기는 약 24 MiB이고 mipmap은 사용하지 않습니다. 파일의 압축 크기와 GPU 비용은 다릅니다.

`createSoulFlame({ texture, columns, rows, frames, fps })`는 `group`, `duration`, `update(seconds)`, `setLayer(name, visible)`, `dispose()`를 제공합니다. 층 이름은 `body`와 `halo`입니다. 텍스처는 호출자가 소유하여 마지막 인스턴스 제거 후 따로 `dispose()`합니다. 프레임 선택은 역방향 탐색이 가능하며 마지막 프레임에서 멈춥니다. 이 예제의 UI 반복은 효과 재발동이고 연속 불꽃 루프는 아닙니다.

### 작은 자동 검사와 한계
