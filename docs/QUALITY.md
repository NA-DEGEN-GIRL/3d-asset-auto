# 용도에 맞춘 품질 명세와 검사

제작·수정 전에 요청의 핵심 기능과 외관에 대해 **관찰 가능한 합격 기준**을 몇 가지 정합니다. "자연스럽다"만 쓰기보다 어느 거리·방향·상태에서 무엇이 보여야 하고 어떤 결함이 없어야 하는지 적습니다. LLM은 요청·프로젝트·실제 모델에서 필요한 가정을 추론하고, 이미 알 수 있는 값을 매번 사용자에게 묻지 않습니다. 특정 부위의 토폴로지나 특정 동작의 리듬을 모든 에셋에 강제하지 않습니다.

`features`에는 **표현 방식 → 의도한 기능 → 허용 범위/합격 기준 → 알려진 제한**을 자유롭게 기록합니다. 단순 표면, 변형 메시, 강체 조립, 골격 등은 서로 다른 구현 선택입니다. 정지 외관이 같아도 가동 범위·관찰 방향·다른 부품과의 관계에서는 다를 수 있으므로 실제 사용 범위의 끝과 전환 시점을 확인합니다. 예를 들어 얇은 표면의 뒷면 노출과 회전 조립체의 축·간극 검토는 서로 다른 기준입니다. 이런 예시는 적용 대상을 판단하기 위한 것이며 고정 체크리스트가 아닙니다.

정적 소품의 좁은 수정은 짧은 기준 메모와 관련 렌더로 충분할 수 있습니다. 사용 조건을 전달하거나 측정을 반복할 필요가 있으면 명세를 `.work/`에 작성하고, 완료된 정확한 revision에 선택적 `assess`를 실행해 `usage.json`과 검사 기록으로 남깁니다. 엔진이나 웹앱은 필요하지 않습니다.

## 동작 참고 자료 활용

복잡하거나 익숙하지 않은 동작, 목표 자세·접촉이 불분명한 동작, 자연스러움 검토에서 반복해 실패한 동작은 추가 수정 전에 이미지·영상으로 목표를 구체화합니다. 제공된 자료나 검토 가능한 기존 모션을 활용하고, 주요 자세를 나눠 보는 것이 도움이 되면 사용 가능한 ImageGen 등의 이미지 생성 도구로 자세 시트를 만듭니다. 목표가 명확한 간단한 수정은 기존 자료를 재사용하며, 참고 수집·생성도 작업 예산 안에서 수행합니다.

자료에서 **동작 단계·핵심 자세·지지점과 접촉의 시작/해제·움직이는 방향** 중 필요한 정보를 정리합니다. 출처 경로나 URL, 생성 자료 여부, 사용할 패널/시점과 대상 클립·사건을 짧게 기록합니다. 대상 캐릭터의 비율·가동 범위·장비·스타일에 맞게 해석한 목표 자세를 실제 리그에서 만들고, 참고와 렌더의 차이를 구체적인 포즈·접촉 수정으로 연결합니다. 목표 자세를 맞춰도 표면이 무너지면 아래 단계별 진단으로 원인을 구분합니다.

생성한 시트는 관절 구조와 좌우, 체형·장비·접촉 관계가 패널 사이에 일관적인지 먼저 검사합니다. 불가능한 자세나 불일치는 수정·제외하고, 가림·원근 때문에 알 수 없는 깊이를 확정된 3D 구조로 취급하지 않습니다. 필요한 다른 각도나 실제 동작 자료를 확인하고 남은 불확실성은 기록합니다. 생성 이미지는 설계 가설이며 실제 해부학·물리의 정답이 아닙니다. 참고 이미지 자체를 결과물의 렌더나 검토 통과 증거로 사용하지 않습니다.

패널 번호가 달라도 같은 자세를 반복하거나 좌우 팔다리·지지점이 뒤바뀌면 새로운 단계나 올바른 교대로 세지 않습니다. 의도된 정지·정착 구간의 반복은 허용하되 실제 진행과 구분합니다. 색상 표식이나 패널 수를 늘린 것만으로 일관성이 확보됐다고 판단하지 않습니다. 핵심 순서·접촉·타이밍을 이미지로 판단할 수 없거나 보완 후에도 모순이 남으면, 같은 시트를 계속 늘리기보다 확인 가능한 기존 모션의 시점별 자료나 실제 영상으로 전환합니다. 기존 Kimodo 소스도 활용할 수 있지만 새 Kimodo 설치·추론은 여전히 명시적 선택이 필요합니다. 대체 자료에서도 대상 동작에 맞는 부분과 남은 한계를 검토하고 채택·제외 이유를 기록합니다.

정지 이미지의 순서나 간격만으로 동작의 속도·리듬·연결을 검증할 수 없습니다. 영상은 재생 속도와 시간 정보를 확인해 참고하고, 대상 동작은 의도한 속도의 실제 재생이나 시간 간격을 보존한 렌더 시퀀스로 확인합니다. 최종 GLB에서도 대응하는 자세·접촉 사건과 그 사이 전환을 재검토합니다. 참고 자료는 LLM의 설계·보정에 사용하며, 현재 런타임에 이미지·영상에서 모션을 자동 추출하는 기능이 있다는 뜻은 아닙니다.

## 여러 클립의 개별 완성

여러 동작을 요청받으면 **요청한 클립마다** 목적·합격 기준, 필요한 단계/접촉 사건과 참고 자료, 실제 검토 증거, 남은 결함·작업 상태를 짧게 기록합니다. 일부 대표 클립의 성공으로 나머지를 승인하지 않습니다. 형식적인 문서 분량보다 각 클립에서 무엇을 만들고 확인해야 하는지가 드러나는 기록이면 충분합니다.

참고 이미지를 생성할 때 기본 단위는 **개별 클립의 자세 시트 또는 참고 자료 묶음**입니다. 같은 클립의 여러 단계를 한 시트에 구성해도 되지만, 각 자세와 접촉 관계를 충분히 읽을 수 있어야 합니다. 서로 다른 동작을 한두 자세씩 모은 이미지는 전체 기획에 활용하며, 각 클립에 필요한 단계·전환의 목표가 빠져 있으면 별도 시트나 자료로 보완합니다. 단순히 패널 수를 늘려 자세를 알아보기 어려워지면 시트를 나누고, 가려진 접촉이나 깊이는 필요한 각도·근접 자료를 추가합니다. 이미지·패널 수를 모든 동작에 고정하지 않으며, 동작이 많다는 이유로 전체를 한두 장에 맞추지 않습니다.

체형·장비·기준 자세처럼 공통으로 확인한 정보는 재사용할 수 있습니다. 다만 각 동작의 고유한 가동 범위·접촉·전환 목표까지 공통 자료로 확인됐다고 가정하지 않습니다. 위의 참고 활용 조건에 해당하지 않는 명확한 단순 수정에는 새 이미지 생성을 강제하지 않습니다. 자료의 충분함은 장수가 아니라 해당 클립을 구체적으로 설계하고 실제 결과와 비교할 수 있는지로 판단합니다.

진행은 클립별 또는 밀접한 소수 클립별로 **참고와 목표 정리 → 제작 → 다각도·재생 검토 → 필요한 수정 → 새 출력 재검사**를 수행하고 다음 작업으로 이어갑니다. 공통 스타일·리그를 확인하려고 여러 초안을 먼저 만들 수 있지만 초안 생성과 개별 완성을 구분합니다. 한 클립의 해결이 막히면 원인과 남은 작업을 보존하고 독립적인 클립을 계속 진행합니다. 공유 리그·가중치·제약을 바꾸면 영향받는 기존 클립도 다시 확인합니다. 최종 GLB의 모든 요청 클립에 대해 실제 데이터와 검토 근거를 대조하며, 이름이 전부 있다는 사실만으로 품질을 승인하지 않습니다.

작업량과 반복 예산은 **클립 수·난이도·필요한 관찰 범위**에 맞춰 계획합니다. 임의의 전체 이미지 장수나 호출 횟수에 맞추려고 클립별 검토를 축소하지 않습니다. 작업을 나누어 진행할 때도 완료·진행 중·미착수 항목을 유지하고 전체 요청을 끝까지 이어갑니다. 실제 사용자 시간·비용 제약이나 해결할 수 없는 문제가 있으면 영향을 받는 클립과 남은 작업을 구체적으로 보고하며, 자체적으로 작은 예산을 정한 것을 나머지 생략의 근거로 삼지 않습니다. 이미지 생성과 결과 검토 렌더의 예산은 구분하고, 추가 유료 작업은 기존 승인 범위를 따릅니다.

## 용도에 맞게 관찰하기

일반 사용 거리의 전체 모습으로 비례·실루엣·가독성을 확인하고, **그 화면만으로 핵심 기준을 판정하기 어렵거나 결함이 의심되는 부위**는 확대합니다. 가림이 있으면 각도를 바꾸고, 원인이 불분명하면 조명·재질 표시를 바꿔 구분합니다. 작은 전체 이미지의 확대만으로 정보가 부족하면 해당 부위를 충분한 해상도로 새로 렌더합니다. 확대 화면에서만 좋아 보이는 수정도 전체 모습으로 다시 확인합니다.

아래는 필요한 검토를 고르는 기준이며 모든 에셋에 적용할 고정 체크리스트가 아닙니다.

| 품질을 좌우하는 요소 | 확인할 관계와 증거 |
| --- | --- |
| 부품 간 상호작용 | 지지·연결 구조에서 작용점까지의 연속성, 방향과 회전 중심, 접촉 면의 배치·감김·끼워짐을 함께 봅니다. 접촉부와 연결된 장비·조립체 전체가 이동하는 공간을 실제 형상으로 확인하며, 주변 몸·복장·부품과의 의도하지 않은 관통·뜸을 찾습니다. 기준점 일치나 충돌체·물리 설정의 존재만으로 접촉과 기능을 승인하지 않습니다. |
| 형상·표면·재질 | 의도하지 않은 구멍·찌그러짐·노이즈·음영 이상·텍스처 이음새가 요구된 외관을 해치는지 확인합니다. 기하·노멀·재질 문제를 구분해 고치며, 의도된 열린 경계·얇은 표면·UV 분할이나 스타일을 일괄 용접·평활화로 없애지 않습니다. |
| 시간에 따른 변화 | 핵심 자세뿐 아니라 그 사이의 연결, 작동 범위 끝과 상호작용의 시작·해제 구간을 봅니다. 타이밍이 품질 기준이면 의도한 속도로 재생하고, 반복 동작은 여러 주기의 연결 튐·의도하지 않은 멈춤·속도 변화를 확인합니다. 이동 동작은 지지 구간의 접촉점과 바닥 사이 미끄러짐도 검토합니다. 순간 자세와 시작·끝 수치만으로 움직임의 품질을 승인하지 않습니다. |

관찰 대상은 최종 GLB에서 확인합니다. 원본 `.blend`의 자세가 올바르더라도 내보내기 뒤의 변형·재질·클립이 같다고 가정하지 않습니다. 핵심 시점 PNG는 자세 비교에, 로컬 재생이나 시간 간격을 보존한 렌더 시퀀스는 전환·리듬 검토에 사용합니다. 도구상 재생을 관찰하지 못했다면 그 범위를 미검토로 남깁니다. 이를 위해 별도 웹앱을 만드는 절차를 강제하지 않습니다.

후처리 중 생긴 표면 문제는 [발생 단계 진단과 마감 사례](FINISHING.md)를 참고해 생성 원본·메시 정리·리깅·출력을 비교합니다. UV·노멀 이음매의 정점 분리, 실제 구멍, 떠 있는 성분을 구분하고 확인된 원인에 맞춰 복구합니다.

애니메이션의 주요 상태는 **같은 시점을 서로 보완하는 여러 각도**에서 확인합니다. 정면·측면을 기본으로 삼고 반대편이나 뒤에 가려진 변형·접촉은 그 방향을 추가합니다. 한 방향의 시간 샘플 여러 장이나 정지 자세의 5방향 이미지만으로 전체 동작을 승인하지 않습니다. 좁은 수정에서는 영향 범위에 맞춰 검토하되 보지 못한 방향·상태는 명시합니다.

## 리그와 동작의 단계별 진단

리그를 새로 만들거나 변경했거나 사용할 범위의 검증 기록이 없다면, 복잡한 클립을 만들기 전에 필요한 관절 사슬을 짧은 독립 포즈로 움직여 봅니다. 기준 자세에서 굽힘·비틀림을 분리해 회전축·굽힘 방향과 실제 메시 변형을 확인합니다. 끝점 위치나 각도 제한을 맞춰도 중간 관절의 뒤집힘·심한 접힘이 남으면 실패입니다. 같은 리그·메시·가중치·제약과 가동 범위를 검증한 근거는 재사용하고, 바뀐 부분과 그 영향부터 다시 확인합니다.

생명체는 종·체형·스타일과 사용할 동작 범위에 맞게 관절의 방향·연결 구조와 표면의 부피·접힘을 봅니다. 실제 뼈·살·근육을 각각 모델링하거나 근육 시뮬레이션을 일괄 추가할 필요는 없습니다. 골격 움직임이 맞는데 표면이 납작해지거나 꼬이면 가중치 분포·관절 주변 메시·자세별 보정 형태 중 원인에 맞는 수단을 선택합니다. 보정은 해당 자세뿐 아니라 그 전후와 다른 사용 자세에서도 확인하며, 의도된 스타일 변형과 원치 않는 부피 손실을 구분합니다.

Blender의 [Armature Preserve Volume](https://docs.blender.org/manual/en/latest/modeling/modifiers/deform/armature.html)은 관절 회전에서 생기는 부피 손실을 줄이는 선택지입니다. 설정 변경·보정 형태·드라이버가 Blender 안에서 좋아 보인다는 사실만으로 전달 결과를 승인하지 않습니다. 보정 방식의 출력 지원을 확인하고 최종 GLB에서 같은 자세와 전환을 비교합니다.

결함은 **처음 나타나는 단계와 그 전 단계**를 비교해 좁힙니다. 아래에서 실제 작업에 존재하고 진단에 필요한 단계를 선택하며, 단위·방향·기준 자세와 대응하는 사건 시점을 맞춥니다. 중간 출력이 없으면 원인을 미확인으로 기록하고 생성 모델이나 리그의 결함으로 단정하지 않습니다.

| 비교 단계 | 구분할 문제와 다음 확인 |
| --- | --- |
| 원본 모션과 원본 골격 | 요청한 동작·타이밍·이동이 원본부터 어긋나는지 봅니다. 입력이나 모션 자체의 문제인지 확인한 뒤 수정·재생성을 판단합니다. |
| 대상 골격에 적용한 모션 | 원본과 대상의 대응 자세를 비교해 뼈 매핑·기준 자세·회전축·계층·스케일·제약의 영향을 확인합니다. |
| 골격과 변형된 메시 | 뼈는 의도대로 움직이는데 표면만 무너지면 바인딩·가중치·변형 처리를 확인합니다. 정지 상태와 변형 상태를 비교하고, 기하 결함과 노멀·재질의 음영 문제를 구분합니다. |
| 장비·접촉·구속을 포함한 조립 상태 | 같은 동작에서 필요에 따라 장비 유무를 비교합니다. 가려진 변형과 장착·구속으로 생긴 문제를 구분하고, 장비의 표시 여부와 제약의 활성 여부를 기록합니다. 최종 사용 상태의 전체 형상과 접촉은 따로 확인합니다. |
| 내보내기 전 상태와 최종 GLB | 재가져온 GLB의 같은 사건에서 자세·변형·재질·클립을 비교합니다. 출력·보간·병합에서 생긴 문제는 그 단계에서 수정합니다. |

진단용 포즈·장비 착탈·제약 변경은 사본이나 별도 revision에서 수행하고 전달 클립에 섞지 않습니다. 중간 결과를 재사용해 확인된 원인에 맞는 수정을 선택합니다. 리타게팅·가중치·접촉 문제를 해결하려고 원본 모션 추론을 무작정 반복하지 않습니다. 이는 LLM의 비교·수정 절차이며 `assess`가 단계별 원인을 자동 분류하는 기능은 아닙니다.

## 동작의 의미와 접촉 사건

상호작용이 있는 동작은 용도에 맞게 준비·작용·회복과 접촉의 시작·유지·해제를 구분합니다. 실제 사건을 `events`로 표시하고 필요한 접촉 구간·방향·작용 결과를 `acceptance`에 기록합니다. 물체를 놓거나 발사하는 동작이라면 손·대상·구속 해제와 물체가 분리되어 움직이기 시작하는 시점을 맞추며, 해제 뒤까지 붙잡는 제약이 남는지 확인합니다. 사건 이름이나 키프레임이 있다는 사실만으로 의미와 타이밍을 승인하지 않습니다.

접촉 보정은 관련된 관절·표면·대상의 움직임을 함께 보며, 접촉 전후 전환에서도 자연스럽게 이어지는지 확인합니다. 장비 종류와 의도에 따라 사건·자세를 고르고, 특정 무기나 캐릭터의 동작 순서를 공통 규칙으로 강제하지 않습니다.

## 결함 수정과 종료 판단

관찰된 결함에는 **해당 기준·위치/클립/시점·revision·재현 가능한 뷰나 증거 경로**와 원인 판단의 근거를 짧게 기록합니다. 관찰 사실과 아직 확인하지 못한 원인 가설을 구분하고, 수정 내용과 재검사 결과를 이어 적습니다. 그다음 **수정 → 새 revision 출력 → 같은 조건에서 재검사**합니다. 수정 전후를 같은 카메라·조명·포즈/시점에서 비교하되, 클립 길이가 바뀌었다면 같은 사건에 대응하는 시점을 사용합니다. 전체 인상과 영향을 받을 연결 부위·인접 동작도 확인합니다. 각도나 조명으로 결함을 숨긴 새 렌더, 수정 스크립트의 성공만으로 해결 처리하지 않습니다.

수정의 부작용도 최종 GLB에서 확인합니다. 관통을 줄인 수정은 관절 방향·변형을, 보간·타이밍 수정은 접촉 유지·해제와 루프 연결을 다시 검사하는 식으로 영향에 맞춰 고릅니다. 요청한 변경 외의 메시·스킨 가중치·재질·기존 클립은 부모와 비교해 보존을 확인합니다. 클립 이름이 같다는 사실만으로 내용·속도가 보존됐다고 판단하지 않습니다. 보존 경로의 데이터·해시 증거를 사용하고, 재내보내기로 표현이 달라졌다면 대응하는 데이터와 시간별 결과를 허용 오차에 맞춰 비교합니다.

개별 동작 수정은 변경할 클립을 먼저 명시하고 [보존 비교 도구](BLENDER.md#개별-클립-수정과-보존-비교)로 나머지 시간·보간·변환 데이터와 모델 문맥을 대조합니다. 재샘플링 등으로 데이터가 달라지면 같은 초 단위 시점의 실제 자세·변형을 비교하고, 길이 변경을 숨기는 정규화된 진행률 비교만으로 승인하지 않습니다.

수치 검사는 구조와 측정값, 시각 검토는 실제 보이는 외관과 동작, 기능 검토는 요청한 사용 조건에서의 성립 여부에 대한 증거입니다. 엔진 import는 별도의 호환성 증거입니다. 관찰된 결함은 다른 종류의 통과로 상쇄되지 않습니다. "프로토타입"은 합의된 상세 수준을 뜻할 수 있지만 이미 요구된 기능의 결함을 면제하지 않습니다. 의도된 생략과 미해결 문제를 구분하고 결과에 맞춰 합격 기준을 몰래 낮추지 않습니다.

반복 예산은 클립 수·난이도·중요도·수정 범위·비용에 맞게 시간, 로컬 연산량 또는 수정 횟수로 정하고 사용자 제약을 우선합니다. 특정 에셋에서 쓴 회전 제한·허용 오차·시도 횟수를 다른 작업의 공통 기준으로 승격하지 않습니다. 필요한 기준이 증거로 충족되면 종료합니다. 개선이 멈추면 원인이나 방법을 재검토하고, 남은 예산으로 해결할 근거가 없거나 예산이 소진되면 가장 나은 revision을 보존해 미완료 상태로 전달합니다. 남은 결함의 발생 조건·용도에 미치는 영향·시도한 수정·다음에 필요한 작업을 구체적으로 보고합니다. 로컬 수정 예산은 유료 재생성 승인이 아니며 추가 호출은 [기존 Tripo 승인 범위](TRIPO.md)를 따릅니다.

## 명세와 명령

`AssessmentRequest`는 `asset_id`, `revision`, 선택적 `usage`, 검사할 `clips`를 받습니다. `usage` 생략 시 해당 revision의 해시가 일치하는 기존 명세를 사용합니다. 명세도 없으면 동작 의미를 추측하지 않고 모든 클립을 미검사로 남깁니다. 명시적 `usage`는 전체 명세를 교체하므로 기존 내용을 유지하려면 먼저 읽어 합칩니다.

다음은 형식 예시입니다. 이름과 기준은 실제 에셋과 목적에 맞춥니다:

```json
{
  "asset_id": "moving-device",
  "revision": "EXACT_COMPLETED_REVISION",
  "usage": {
    "purpose": "게임에서 상호작용하는 기계 소품",
    "assumptions": ["일반 플레이 카메라 거리에서 사용"],
    "features": [{
      "name": "moving_assembly",
      "representation": "공통 피벗 아래의 강체 부품",
      "intended_behavior": "정해진 범위에서 열리고 닫힘",
      "acceptance": ["가동 범위 끝에서도 연결 부위가 노출되지 않음"],
      "limitations": ["부품의 탄성 변형은 표현하지 않음"]
    }],
    "clips": {
      "open": {
        "purpose": "한 번 열고 마지막 상태 유지",
        "playback": "hold",
        "motion": "none",
        "events": [{"name": "full_extension", "time_seconds": 0.75}],
        "acceptance": ["최대 가동 시 주변 부품과 간섭하지 않음"]
      },
      "cycle": {
        "purpose": "지속적으로 반복하는 동작",
        "playback": "loop",
        "rules": {
          "position_tolerance_m": 0.002,
          "rotation_tolerance_degrees": 1,
          "max_angular_velocity_jump_dps": 20,
          "max_still_seconds": 0.15
        }
      }
    }
  },
  "sample_rate": 30,
  "max_render_frames": 16
}
```

```sh
uv run --no-sync python -m asset_auto.cli assess .work/assessment.json --async
uv run --no-sync python -m asset_auto.cli job JOB_ID
```

CLI와 MCP `assess_asset(request)`는 같은 파이프라인을 사용합니다. MCP `asset_usage(asset_id, revision)`는 명세와 최신 검사 기록을 읽습니다. 정적인 명세(`clips: {}`)는 Blender를 실행하지 않습니다. 검사할 동작이 있으면 최종 GLB 사본을 Blender로 재가져옵니다. 생성·유료 API 호출이나 소스 재출력은 없습니다.

## 재생 정책과 수치 검사의 범위

`playback`은 `unspecified`, `loop`, `once`, `hold`입니다. `once`는 단발 재생 의도, `hold`는 재생 후 마지막 상태 유지 의도이며 게임의 상태 전환·블렌딩은 프로젝트에서 구현합니다. 반복 동작에만 루프 끝 자세 검사를 적용합니다. 의도적인 준비·멈춤·정지 상태를 허용하고, 정지가 부적절할 때만 `max_still_seconds`를 지정합니다.

`motion`은 `unspecified`, `in_place`, `root_motion`, `none`입니다. 루트 모션에는 관찰한 `root_target`이 필요합니다. 대상 이름은 검사 결과 `targets`에 기록되며 `object:실제객체`, `bone:실제리그/실제뼈`, `morph:실제메시/실제형태키` 형태입니다. 루트에는 object 또는 bone 변환만 쓸 수 있습니다. 이름을 추측하지 말고 `inspect`의 실제 객체·뼈를 확인합니다.

루트 모션의 루프 자세는 지정한 루트의 누적 이동·회전을 제외하되 스케일은 보존 여부를 검사합니다. 루트의 시작·끝 이동량과 평균 변위 속도도 보고합니다. 값은 **부모 로컬 좌표**이므로 부모가 회전·확대되거나 움직이면 게임의 월드 속도로 해석하지 않습니다. `target_speed_mps`는 게임에서 사용할 의도한 속도를 기록하며 자동 속도 맞춤이나 발 접지 증거가 아닙니다. 제자리 동작의 루트 이탈은 `root_target`과 `max_root_drift_m`을 함께 지정하면 검사합니다. 시작점으로 돌아왔더라도 중간 이탈을 측정합니다.

| 측정 | 해석 |
| --- | --- |
| 루프 위치·회전·스케일·morph 차이 | 로컬 변환의 시작·끝 차이. 기본 허용치 1mm, 1도, 스케일/morph 0.001이며 목적에 맞게 변경 |
| 루프 선속도·각속도 차이 | 처음/마지막 구간의 한쪽 차분. `max_linear_velocity_jump_mps`, `max_angular_velocity_jump_dps`가 없으면 측정만 하고 미검사 처리 |
| 저활동 구간 길이 | 모든 로컬 변환·morph의 변화율이 정한 기준 이하인 구간. 정지 의도나 동작 의미를 자동 판정하지 않음 |
| 루트 이탈·변위 | 선택한 루트의 로컬 이동. 발 미끄러짐·지지점 안정성 검사와 다름 |

저활동 임계값은 `still_position_speed_mps`(기본 0.001), `still_rotation_speed_dps`(0.1), `still_value_speed`(0.001)로 조절합니다. 기본값은 범용 품질 보증치가 아닙니다. 반복 경계 양쪽의 저활동 구간은 이어서 계산합니다. 미세 떨림으로 저활동 검사를 통과해도 유용한 동작이라는 뜻이 아닙니다.

접촉·미끄러짐 검토에는 실제 접촉점, 구간, 기준 좌표와 상대 운동이 필요합니다. 질량·무게중심 검토에도 가정이 필요합니다. 자유 서술 `acceptance`와 기능 표현의 적절성은 자동 통과시키지 않으며, LLM이 관련 측정 스크립트·실제 렌더·필요한 프로젝트 실행 근거로 별도 검토합니다. 충돌·접촉·스타일 품질의 일반 자동 판정기는 제공하지 않습니다.

## 핵심 시점과 비용

숫자 검사는 기본 초당 30샘플, 클립당 최대 1201샘플이며 `sample_rate`(2–120), `max_samples_per_clip`(5–10001)로 조절합니다. 한 번에 최대 16클립을 선택합니다. 예산을 넘으면 몰래 간격을 늘리지 않고 요청 수정을 요구합니다. 빠른 동작은 샘플 사이의 변화를 놓칠 수 있습니다.

`events`의 초 단위 시각은 해당 GLB 클립의 실제 타임라인 범위 안에 지정합니다. 이름은 동작 종류와 무관하게 자유롭게 지정합니다. 이벤트 전후, 시작·끝과 그 인접 시점, 저활동 전환, 변환·morph의 최대/최소 변화 시점을 렌더 후보로 뽑습니다. 후보는 시점과 선택 이유를 모두 기록합니다. 자동 극값은 의미 있는 순간의 후보이며, 접촉이나 의도한 사건을 알아낸 증거는 아닙니다.

극값은 위치·회전·스케일·morph 허용치에 비해 의미 있는 변화부터 우선합니다. 이 기준 아래의 작은 변화까지 관찰해야 하면 해당 허용치를 낮추거나 명시적 이벤트를 지정합니다. 부동소수점 수준의 변환 오차가 중요한 렌더 예산을 차지하지 않도록 합니다.

`render: false`는 숫자 분석과 후보 추출만 합니다. 렌더 시 **한 번의 `assess` 호출 안에서** 기본 총 24장(`max_render_frames`: 0–128)을 선택한 클립 간 배분하고 이벤트를 우선합니다. 이는 전체 작업의 이미지 상한이나 참고 이미지 생성 장수가 아닙니다. `views` 기본값은 `["front", "right", "back"]`이며 `left`, `perspective`도 선택할 수 있습니다. 이름은 Blender 월드 기준 카메라 방향이므로 실제 모델 방향과 가림을 보고 선택합니다. 한 시점의 여러 각도를 함께 배분하며 기본 24장은 3방향 × 8시점에 해당합니다. 조명 준비에 추가 정지 이미지를 렌더하지 않습니다.

클립이 많아 필요한 순간을 충분히 볼 수 없으면 `clips`로 한 클립 또는 소수 클립을 선택해 호출을 나누고 각 검토에 필요한 예산을 배정합니다. 전체 `usage.clips` 명세를 유지한 채 검사 대상만 선택합니다. 같은 GLB에 저장된 명세를 재사용하는 후속 호출은 `usage`를 생략할 수 있으며, 단일 클립만 적은 `usage`를 매번 보내 기존 전체 명세를 지우지 않습니다. 각 호출의 `assessments/q.../report.json`과 실제로 검토한 증거 경로를 클립별 작업 기록에 남깁니다. `assessment.json`은 마지막 호출의 결과로 교체되고 `unassessed_clips`도 그 호출의 선택 범위에 대한 값이므로, 여러 호출의 전체 완료 여부는 보존된 기록을 함께 대조합니다.

각 후보의 `views`는 방향별 실제 PNG 경로이고 `file`은 첫 이미지의 호환 필드입니다. `unrendered_views`는 그 시점에서 빠진 각도입니다. 클립의 `view_counts`, `rendered_moments`, `unrendered_frames`, `unrendered_view_images`와 전체 `unassessed_clips`를 읽어 남은 범위를 판단합니다. `rendered_frames`는 시점 수가 아닌 총 이미지 수입니다. 작은 예산 때문에 각도가 일부만 출력될 수 있으며 중요한 사건이 미렌더로 남으면 해당 클립 선택·각도·예산을 조정합니다. PNG를 실제로 보지 않은 상태는 계속 `pending`/`untested`입니다.

기존 생성 경로의 3장 샘플은 같은 `perspective` 카메라의 빠른 개요이고 `animation-previews.json`에 `single_view_overview`로 표시합니다. 가동 범위나 움직임 품질의 근거가 필요할 때 추가 `assess`나 목적에 맞는 다각도 렌더를 사용합니다. 정적인 부분 수정마다 모든 동작을 분석하지 않습니다.

## 전달과 추적

- `usage.json`: 용도·표현·재생 정책·기준과 최종 GLB SHA256. GLB와 함께 전달하는 이 저장소의 메타데이터이며 범용 엔진이 자동 적용하는 표준은 아닙니다.
- `assessment.json`: 최신 검사 기록. 실행 성공, 조건부 수치 결과, 시각 검토, 기능 검토, 프로젝트 검토는 별도입니다.
- `assessments/q.../`: 요청·검사 대상 사본·보고서·PNG를 보존하는 실행별 증거. 실패해도 이전 완료 에셋과 명세는 유지합니다.

수치 `passed`는 설정한 해당 검사의 통과입니다. `untested`는 기준이나 증거가 없다는 뜻입니다. 실제 검토한 범위·증거·결함 상태와 미검토 범위를 `review --notes`에 기록합니다. 이 명령은 에이전트의 판단을 저장할 뿐 자동 품질 판정기가 아닙니다. 검토를 수행했지만 요청의 핵심 기준이 실패하거나 판정할 증거가 부족하면 `--result fail`로 이유를 남깁니다. 검토 자체를 하지 않았다면 통과 기록을 만들지 않습니다. 불필요한 선택적 엔진 검사의 미수행은 실패 이유가 아닙니다. 새로운 revision은 이전 승인을 상속하지 않습니다.

편집 시 명세는 남아 있는 클립 이름에 맞춰 상속하고 **재검사 필요**로 표시합니다. 병합 시 완료된 source revision의 선택·이름 변경을 따라 재생 정책과 이벤트도 옮깁니다. 대체 클립에 명세가 없으면 이전 동작의 정책을 잘못 적용하지 않도록 그 항목을 제거합니다. 외부 GLB만 제공된 경우 사용 조건을 자동 추측하지 않습니다. 형상·이름·시간이 바뀌면 상속된 의도와 이벤트를 LLM이 새 결과에 맞게 갱신합니다.
