# game-vfx 설계 메모

**한국어** | [English](GAME_VFX_DESIGN.en.md)

상태: **프로젝트에 맞춰 제작·재생 방식을 선택하는 스킬과 한정된 예제 구현**. 별도 [game-vfx 스킬](../.agents/skills/game-vfx/SKILL.md), Blender 재료 생성 도구와 불·얼음·번개용 [웹 재생 모듈](../examples/game-vfx/effects.js)을 제공합니다. 예제의 도구 조합을 모든 효과의 기본 경로로 적용하지 않습니다. `asset_auto`의 범용 VFX 생성 명령, 유지보수되는 Mantaflow 내보내기·재생 도구, Houdini·EmberGen 어댑터는 제공하지 않습니다.

## 해결할 문제

현재 VFX 실험은 LLM이 Blender와 렌더러 코드를 작성할 수 있음을 확인했습니다. 하지만 매번 효과를 처음부터 구성해야 하며, 이미지·영상의 완성도가 구현 결과로 자동 전달되지 않습니다. 모델 생성용 스킬에 검토 지침만 추가하거나 이름만 바꾸는 것으로 이 간격은 해결되지 않습니다.

목표는 **LLM의 효과 요청을 검증된 제작 도구와 재사용 가능한 구성으로 실행하고, 실제 게임 표현까지 검토·수정하는 별도 스킬**입니다. 절차적 방식 자체를 금지하지 않습니다. 시뮬레이션·셰이더·템플릿도 유효하며, 기본 도형을 나열한 임시 코드와 검증된 제작 경로를 구분합니다.

## 역할 구분

| 담당 | 역할과 경계 |
| --- | --- |
| `3d-assets` | 모델 생성·편집·리깅·메시 애니메이션. 효과에 필요한 얼음·운석 등의 물체가 있을 때 사용 |
| `game-vfx` | 효과의 형태·시간·레이어, 제작 도구 실행, 재사용 가능한 효과 구성, 대상 렌더러 출력과 검수 |
| 이미지·영상 도구 | 표현 참고와 사용할 수 있는 텍스처 재료. 영상에서 3D 물리나 게임 효과를 자동 복원한다고 가정하지 않음 |
| 대상 게임 | 지형·부착 위치·충돌·피해 사건과 재생 수명. 시각 사건과 실제 게임 판정을 구분 |

메시가 필요 없는 효과에는 TRELLIS·Tripo 설치나 호출을 요구하지 않습니다. 새 물체 모델이 필요하면 `3d-assets`의 생성 원칙을 따르고, 제공된 모델은 재사용합니다. 참고·재질·보조 파티클만 추가하고 요청된 입체 움직임을 완성했다고 하지 않습니다.

## 실제로 갖춰야 할 것

- **검증한 제작 경로:** 설치 상태 확인, 실제 실행, 설정·시드·출력·버전 기록, 실패 복구가 가능한 도구 연결. MCP는 필요한 접근 방식일 때만 선택하고, 작동하는 CLI나 스크립트 경로를 우선 재사용합니다.
- **재사용할 효과 구성:** 편집 가능한 원본·재료·표현 의도와 사건 명세를 보존합니다. 해당하면 시뮬레이션 설정과 베이크도 포함합니다. 각 엔진의 셰이더·입자·장면 구현은 별도로 맞추며 한 예제의 수치나 코드를 모든 효과에 고정하지 않습니다. 리소스 이용 조건을 함께 보존합니다.
- **재생 계약:** 필요한 파일, 좌표·크기·시간, 사건 위치, 시작·충돌·중단·재발동·종료와 자원 소유권. GLB에 담기는 모델/클립과 엔진별 동작을 구분합니다. 엔진 미정이어도 요청한 출력 형식을 우선하고 필요한 재료·명세와 통합 미검증 범위를 함께 전달합니다.
- **표현 검수:** 사용자 요청과 채택한 참고에 맞춰 합격 기준을 정하고, 시작 예제가 쉽게 구현하는 수준으로 낮추지 않습니다. 큰 형태와 사건의 리듬을 먼저 맞추고, 종속된 효과가 각 발생 위치·시점을 따르는지 검토합니다. 정상 속도·거리에서 전체 표현을 비교하며, 입자·발광의 양이나 오류 없는 정지 화면만으로 완료 처리하지 않습니다. 주효과가 자유 시점의 입체 표현을 요구한다면 전체 영상을 평면에 재생하는 것으로 대체하지 않습니다.

## 프로젝트에서 제작·재생 경로 선택하기

먼저 실제 프로젝트의 엔진·렌더러·버전·렌더링 경로와 기존 효과 구성을 읽습니다. 대상 장치·해상도·카메라 범위, 크기·방향·접촉·부착·충돌 등 상호작용, 참고와 품질 목표를 확인합니다. 그 조건에서 필요한 데이터를 만드는 도구와 최종 재생 구현을 각각 선택합니다. Blender는 필요한 재료 저작·베이크에 우선 활용할 수 있는 기존 로컬 도구이며 모든 효과의 필수 단계는 아닙니다.

| 선택지 | 적합한 작업 | 확인할 경계 |
| --- | --- | --- |
| 기존 Blender | 편집 가능한 곡선·메시, 노이즈·텍스처 저작, 애니메이션과 필요한 시뮬레이션 베이크 | 제공된 도구는 노이즈·번개 경로를 만듦. 볼륨·물리 캐시의 대상 전달은 별도 경로 확인 필요 |
| 절차적 스크립트·재질 도구 | 필드·궤적·리본·셰이더와 재사용할 설정 | 요청한 형태·시간 변화와 사용 카메라에서 품질 확인 |
| 대상 엔진의 효과 시스템 | 재료 조합, 파티클·재질·장면과 게임 사건 연결 | 해당 버전·렌더링 경로·장치에서 표현·수명·성능 확인 |
| 추가 DCC·시뮬레이션 도구 | 기존 도구로 해결하지 못한 구체적인 제작 필요 | 설치·라이선스·자동 제어·출력 경로를 확인하며 기본 의존성으로 추가하지 않음 |

시뮬레이션은 선택한 표현을 만드는 방법이며 실행 성공이나 물리 계산 자체가 품질 보증은 아닙니다. 별도 로컬 Mantaflow 화염구 실험의 [관찰 범위와 미완료 항목](VFX.md#보존한-저작-실험)을 제공된 예제 기능과 구분합니다. 엔진 미정이어도 요청한 출력 형식을 우선해 제작하고 필요한 원본·재료·명세를 함께 전달하며, Godot와 웹을 자동으로 함께 만들지 않습니다.

공식 기능 참고: [Blender 자동화](https://docs.blender.org/manual/en/4.5/advanced/command_line/index.html), [Godot 3D 파티클](https://docs.godotengine.org/en/stable/tutorials/3d/particles/index.html). 제공된 Blender 도구는 Python으로 실행하며 별도 MCP를 요구하지 않습니다. 아래 Three.js 갤러리는 요청한 웹 미리보기에 사용하는 예제입니다.

## 첫 구현의 판단 기준

한정된 효과 종류와 전달 대상을 골라, 선택한 제작 경로가 참고 준비 → 실제 도구 실행 → 출력 → 대상 재생까지 이어지는지 작은 사례로 확인합니다. 다음 조건을 확인하기 전에는 범용 VFX 생성 스킬로 안내하지 않습니다.

- 선택한 도구의 실제 실행과 사용한 구성·출력이 기록되어 있고, 이미지나 영상만 제시한 결과가 아님.
- 효과의 크기·타이밍·방향 등 의미 있는 요청 변경을 같은 구성으로 처리하며, 매번 전체 코드를 다시 작성할 필요가 없음.
- 채택한 표현이 최종 대상에서 확인되고, 입체성·투명도·접촉·수명·동시 사용 중 해당 조건을 검토함.
- 생성형 모델, 시뮬레이션, 저작 코드의 역할과 미검증 범위를 구분해 보고함.

기존 [VFX 실험](VFX.md), `examples/vfx-web/`, 강체 검사와 로컬 결과물은 보존합니다. 첫 구현은 아래 세 표현에 한정되며 범용 효과 생성이나 상용 게임 품질을 보증하지 않습니다. 스킬에는 핵심 판단을 두고 제작·출력 상세를 필요할 때 읽도록 분리했습니다.

스킬 자체의 적용성을 평가할 때는 [독립 세션 테스트](VFX_TESTING.md)로 실제 요청을 수행하고 근거를 작성 세션에 전달합니다. 일반 효과 제작마다 별도 평가 보고서 전체를 요구하는 절차는 아닙니다.

## 불·얼음·번개 예제 실행

| 예제 | 실제 제작·재생 | 파일 밖에 남는 동작 |
| --- | --- | --- |
| 불 | Blender의 반복 가능한 3D 노이즈 → 갈라진 화염 덩어리로 이루어진 공간 회오리, 위로 전파되는 분출과 냉각 | 화염·시간·불씨·지면 잔열은 Three.js 코드. 저작한 밀도장이지 유체 해석이나 전체 영상 평면 재생이 아님 |
| 얼음 | 기존 TRELLIS 모델·Blender 강체 베이크 → 가속하도록 재생 시간을 조절한 시간차 낙하·파편 운동 | 각 충돌 위치·시점의 작은 파편·얼음 가루·냉기·서리와 재질·수명은 웹 코드. 큰 파편은 원본의 평평한 바닥 베이크를 재생하며 실시간 충돌이 아님 |
| 번개 | Blender의 크게 꺾이는 줄기·분기 경로 → 내려오는 선행 방전, 귀환 방전과 지면 전류 | 경로의 순차 노출·재방전·잔류 전류·빛은 웹 코드로 연출. 실제 전기/충돌 해석이 아님 |

Blender 실행 파일을 확인한 뒤 새 출력 폴더에 재료를 만듭니다. 아래 `<blender>`는 해당 실행 파일 경로입니다.

```text
<blender> --background --python .agents/skills/game-vfx/scripts/prepare_blender.py -- --output .work/game-vfx/bake-r1 --seed 17
```

`source.blend`, `noise.png`, `recipes.json`, `recipe-geometry.glb`, `provenance.json`이 생성됩니다. 기존 출력 폴더를 덮어쓰지 않습니다. `recipe-geometry.glb`는 번개 경로의 정적 형상이며 세 효과 전체를 담은 GLB가 아닙니다.

미리보기용 폴더에는 `noise.png`, `recipes.json`, `ice.glb`, `fire.png`, `ice.png`, `lightning.png`를 준비합니다. PNG 세 장은 효과별 참고 이미지이며 `fire.mp4`, `ice.mp4`, `lightning.mp4`는 선택적 참고 영상입니다. 얼음 GLB에는 `ice_fall_break` 클립이 필요합니다. 이 예제의 원본은 6초, 충돌 2초, 시작 오프셋 `1/24`초이며 다른 클립을 쓰면 재생 코드와 명세를 함께 조정합니다. 생성 미디어는 Git에 없으므로 새 clone은 이 재료를 준비해야 합니다. 불·번개만 다른 프로젝트에서 쓸 때는 얼음 GLB가 필요하지 않습니다.

```sh
node examples/game-vfx/build.mjs --media-dir .work/game-vfx/media
uv run --no-sync python -m http.server 8776 --bind 127.0.0.1 --directory .work/game-vfx/site
```

`web/node_modules`가 없다면 `npm --prefix web ci`로 웹 의존성만 설치합니다. [미리보기](http://127.0.0.1:8776/)에는 세 효과 선택·시간 이동·시점·속도·크기·배경·겹침·보조 층 검토가 있습니다. 사이트 디렉터리만 제공하며 계정·생성 API를 노출하지 않습니다.

`createEffect(id, options)`는 `group`, `duration`, `impact`, `update(seconds)`, `setLayer(name, visible)`, `setSceneDepth(texture, width, height)`, `dispose()`를 제공합니다. `seed`, `scale`, `speed`로 재사용하고 `group` 변환으로 배치합니다. 속도는 모듈과 외부 시계 양쪽에서 중복 적용하지 않습니다. 호출자가 제공한 텍스처·GLB 자원은 호출자가 소유하며, 종료한 인스턴스만 제거해도 다른 인스턴스가 유지됩니다. 실제 데이터 계약과 수정 지침은 [runtime.md](../.agents/skills/game-vfx/references/runtime.md)를 따릅니다.

`effects.js`는 효과 선택과 공통 재생·수명 계약을 담당합니다. 표현은 [fire.js](../examples/game-vfx/fire.js), [ice.js](../examples/game-vfx/ice.js), [lightning.js](../examples/game-vfx/lightning.js)로 분리하고, 자원 관리와 공통 재료는 [common.js](../examples/game-vfx/common.js)를 재사용합니다. 특정 효과를 다듬을 때 다른 효과의 코드까지 다시 작성할 필요는 없습니다.

```sh
node examples/game-vfx/build.mjs --test
node .work/game-vfx/effects.test.cjs
```

자동 검사는 시간 이동·재발동·유효한 좌표·인스턴스 독립·자원 소유권에 더해, 합성 입력에서 얼음의 개별 충돌 위치·시점과 해당 시점의 클립 재생, 번개의 선행 방전 → 접촉 → 지면 전류 순서를 확인합니다. 이는 표현의 자연스러움이나 상용 게임과의 품질 동등성을 판정하지 않습니다. 브라우저 시각 검수, 다른 엔진, 저사양 장치나 다수 동시 효과의 성능 검증도 별도입니다.

## 설치와 라이선스

개인 스킬 폴더의 `game-vfx`를 저장소의 `.agents/skills/game-vfx`에 연결합니다. 다른 작업 폴더에서는 연결을 해석해 실제 저장소를 찾으므로 개발자 PC 경로를 복사하지 않습니다. 기본 모델 생성 설치는 VFX 재료 저작의 필수 조건이 아닙니다.

새 [웹 예제 코드](../examples/game-vfx/LICENSE.txt)는 MIT, 새 Blender `bpy` [도구](../.agents/skills/game-vfx/scripts/prepare_blender.py)는 [GPL-3.0-or-later](../.agents/skills/game-vfx/scripts/COPYING.txt)로 범위를 구분합니다. 나머지 저장소나 외부 미디어의 라이선스를 이 변경으로 다시 지정하지 않습니다. Blender 출력물과 공개 Python 애드온의 조건은 서로 다릅니다. [Blender 공식 안내](https://www.blender.org/about/license/)와 외부 입력·생성 서비스의 이용 조건을 확인하며 출처를 보존합니다. 배포용 웹 빌드는 Three.js 고지를 함께 포함합니다.
