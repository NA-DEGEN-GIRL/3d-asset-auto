# 이미지와 생성 영상으로 동작 설계하기

**한국어** | [English](MOTION_REFERENCES.en.md)

복잡하거나 창의적인 애니메이션은 초기 설계에서 이미지와 시간에 따른 참고 자료를 함께 고릅니다. ImageGen 등의 이미지 도구는 주요 자세·외형을, 기존 모션·영상 또는 생성 영상은 전환·리듬·접촉 사건을 구체화하는 데 씁니다. 반복 실패 후에만 영상을 사용하는 것은 아닙니다. 검토된 기존 자료가 충분하면 재사용하고, 모든 동작에 새 이미지와 새 영상을 의무화하지 않습니다.

이 가이드는 LLM의 참고 수집과 Blender 저작을 연결합니다. 영상에서 골격을 자동 추출하거나 Kimodo에 영상을 입력하는 런타임 기능은 제공하지 않습니다. 새 메시의 기본 TRELLIS.2 경로와 Kimodo·Tripo의 명시적 선택 조건은 유지됩니다.

## 참고를 실제 수정으로 연결하기

1. **클립별로 보존할 표현을 정합니다.** 재생 목적·이동·접촉 조건과 함께, 동작을 특징짓는 최대 자세·실루엣, 주요 부위의 이동 궤적, 몸통과 팔다리 또는 연결 부위의 선후 관계, 가속·감속 중 필요한 항목을 관찰 가능한 목표로 정합니다. 준비·작용·회복이라는 단계 이름만으로 요약하지 않습니다. 큰 동작은 그 폭과 리듬을, 미세한 대기 동작은 절제된 변화를 보존하며 모든 클립을 크게 만들지는 않습니다.
2. **일관된 기준 이미지를 준비합니다.** 제공된 자료, 검토한 자세 이미지, 실제 대상 모델의 렌더를 활용합니다. 새로운 자세를 구체화할 자료가 부족하면 초기 설계에서 ImageGen 등으로 클립별 참고를 만듭니다. 필요한 팔다리·장비와 이동 여유가 보이는 구도로 만들고 이미지 자체의 결함을 먼저 확인합니다.
3. **시간 자료가 필요한 부분을 영상으로 봅니다.** 생성할 때는 한 클립 또는 이어지는 한 구간을 고정 카메라·읽기 쉬운 배경·의도한 속도의 연속 촬영으로 요청합니다. 클립을 여러 구간으로 나누면 연결 사건을 명시하고 경계를 검사합니다. 영상 제작 스킬의 카메라 이동·컷 전환 기본값을 동작 연구에 그대로 적용하지 않습니다.
4. **채택·제외할 관찰을 구분합니다.** 전체 진행과 사건 주변 프레임을 시간 정보와 함께 확인합니다. 좌우 변경, 사라짐·중복, 형태 흔들림, 가려진 접촉, 잘린 장비, 과도한 정지 구간을 찾습니다. 의도된 과장과 형태 오류·불가능한 자세·미확인 깊이를 구분하고 제외한 부분과 이유를 남깁니다. 반복 동작은 실제 한 주기와 여러 주기의 연결을 확인합니다. 영상이 매끄럽다는 사실만으로 물리·그립·루프를 승인하지 않습니다.
5. **채택한 표현을 Blender에서 구현합니다.** 대상 비율·장비·게임 용도에 맞게 해석하되 목표 자세와 경로를 실제 리그에서 시험하고 [단계별 진단](QUALITY.md#리그와-동작의-단계별-진단)으로 차이의 원인을 확인합니다. 타이밍만 수정하는 범위는 요청이 그에 한정되거나 채택한 자세·궤적이 이미 충족된 경우에 선택하며, 필요한 표현이 빠진 결과를 타이밍 실험으로 바꿔 완료 처리하지 않습니다. 실제 수정 범위를 기록하고 골격·장비·접촉 제약·보정 morph·사용 조건의 사건 시간을 함께 맞춥니다.

한 영상에서 보이지 않는 깊이·반대편은 미확인입니다. 서로 따로 생성한 정면·측면 영상도 같은 3D 동작이라고 가정하지 않습니다. 최종 모델에서는 [같은 주요 시점의 다각도 검사](QUALITY.md#리그와-동작의-단계별-진단), 전환과 재생을 확인합니다. 생성 참고의 외관을 결과물의 검토 증거로 사용하지 않습니다.

## 참고와 최종 동작 비교

채택한 표현을 판정할 수 있는 사건을 골라 **참고와 최종 GLB 렌더를 나란히 비교**합니다. 준비·최대 확장·타격/방출·회복 등 해당 클립에 의미 있는 순간과 그 사이 궤적을 고르고, 가능한 한 관찰 방향과 피사체의 화면상 크기를 맞춥니다. 차이를 감추는 카메라나 프레임을 고르지 않습니다. 카메라 이동·원근·가림 때문에 비교할 수 없는 부분은 미확인으로 남기고, 깊이·관통은 최종 모델의 보완 각도에서 검사합니다.

참고 시각과 대상 클립 시각의 사건 대응을 기록합니다. 길이나 속도를 바꿨다면 의도한 시간 변환과 남은 차이를 명시하고, 정규화된 진행률만으로 대응시키지 않습니다. 원래 시간 정보를 보존한 재생·렌더 시퀀스로 양쪽의 전환·속도·리듬을 비교하며, 사건을 정렬해 비교할 때도 각 구간의 실제 길이를 드러냅니다. 채택한 표현마다 달성한 부분과 실제 차이를 기록하고 [수정·회귀 검사와 종료 판단](QUALITY.md#결함-수정과-종료-판단)에 사용합니다.

## Grok Build headless 사용

Grok는 필요한 경우 쓰는 외부 참고 도구이며 이 런타임의 필수 의존성이 아닙니다. 사용할 실행 파일의 `grok --help`와 버전을 확인하고 해당 세션에 실제 `image_to_video` 도구가 있는지 확인합니다. 설치된 스킬 문서만으로 도구나 로그인 상태를 추정하지 않습니다. 연결된 계정과 허용된 작업·비용 범위 안에서 진행하고, 같은 승인 범위의 작업을 매번 재확인하지 않습니다. 입력 이미지는 선택한 영상 서비스로 전송되며 인증은 Grok에 맡깁니다. 키를 요청 명세나 저장소로 복사하지 않습니다.

로컬에서 확인한 스킬 이름은 `imagine`과 `game-animation-frames`입니다. 전용 스킬 호출 도구가 없어도 세션에 안내된 `SKILL.md`를 읽을 수 있었습니다. 개인 PC의 스킬 경로나 특정 CLI 버전의 도구 인자를 다른 설치에 고정하지 않습니다.

프롬프트 파일에는 다음을 구체적으로 적습니다.

- 확인한 입력 이미지의 절대 경로, 한 동작의 목표와 관찰 조건, 실제 도구가 지원하는 길이.
- 한 번의 `image_to_video` 실행과 그 결과 확인. 실패·응답 유실 시 재제출하지 말고 반환된 식별자를 보존할 것.
- 다른 생성 서비스·추가 변형·설치·설정 변경을 요청 범위 밖에서 실행하지 않을 것.
- 도구가 반환한 실제 결과 경로와 상태를 보고할 것. 메타데이터 저장은 호출한 쪽이 처리할 수 있으므로 Grok의 파일 쓰기를 필수로 만들지 않을 것.

현재 설치의 옵션을 확인한 뒤 적용할 headless 예시입니다. 경로를 실제 절대 경로로 바꿉니다.

```sh
grok --help
grok --cwd "/absolute/runtime/.work/motion-reference" --prompt-file "/absolute/runtime/.work/motion-reference/request.md" --output-format streaming-json --tools read_file,image_to_video --allow read_file --allow image_to_video --permission-mode dontAsk --no-subagents --max-turns 4 > "/absolute/runtime/.work/motion-reference/events.jsonl"
```

`max-turns`는 이 호출의 대화 길이 제한이며 영상 생성 횟수·과금 상한이 아닙니다. 프롬프트의 실행 범위와 실제 이벤트 기록을 함께 확인합니다. headless에서 기능을 제공하면 대화형 조작이나 새 MCP를 추가할 필요가 없습니다. 실제 기능 차이나 여러 클라이언트의 공통 호출 요구가 확인될 때만 별도 어댑터를 검토합니다. 이 명령은 Grok CLI 호출이며 `asset_auto`의 새 provider나 MCP 메서드가 아닙니다.

## 결과 보존과 프레임 검사

생성 세션이 끝났다는 사실과 영상 도구가 완료됐다는 사실을 분리합니다. `streaming-json`의 실제 `image_to_video` 호출과 완료 결과, 반환 경로를 확인합니다. **영상 완료 뒤 기록 저장이 실패해도 영상을 다시 생성하지 않습니다.** 반환 파일의 존재와 디코딩을 확인하고 작업 폴더에 복사해 SHA256, 입력 이미지·프롬프트, 세션/작업 식별자와 함께 보존합니다. 미확인 제출은 재시도 전에 조정합니다.

FFprobe/FFmpeg가 있으면 실제 길이·FPS·프레임 시각을 읽고 검토용 프레임을 추출할 수 있습니다. 아래는 기존 영상을 읽는 예시이며 출력 디렉터리를 먼저 준비합니다.

```sh
ffprobe -v error -select_streams v:0 -show_streams -show_format -show_frames -show_entries "frame=best_effort_timestamp_time:stream=width,height,avg_frame_rate,nb_frames:format=duration" -of json reference.mp4
ffmpeg -hide_banner -loglevel error -n -i reference.mp4 -an -fps_mode passthrough frames/%04d.png
```

PNG 순서와 원본 프레임 시각을 대응시킵니다. 낮은 FPS의 개요 시트가 놓칠 수 있는 접촉·해제·급격한 움직임은 원본의 인접 프레임을 더 촘촘하게 확인합니다. 시트의 칸 수나 프레임 번호를 균일한 동작 단계·재생 속도로 오해하지 않습니다. 실제 재생을 보지 못했다면 시간 순서 프레임 검사와 구분해 보고합니다.

검토 메모에는 채택·제외한 구간과 이유, 원본 시각에서 대상 클립 시각으로의 변환, 실제 수정 범위와 미확인 사항을 남깁니다. 개별 클립 수정·추가 후에는 [보존 비교](BLENDER.md#개별-클립-수정과-보존-비교)를 수행합니다. 재내보내기가 다른 데이터까지 바꾸면 호환되는 새 클립만 원본 모델에 병합하는 방법을 검토합니다. 영상·프레임·원본 로그·캐릭터 파일은 기본적으로 로컬에 보존합니다.

## 확인한 범위

2026-09-15 Windows Grok Build 1.0.30에서 headless `image_to_video`를 한 번 실행해 실제 캐릭터 렌더로 활쏘기 영상을 생성했습니다. 요청은 6초였고 결과는 24 FPS, 145프레임, 약 6.04초였습니다. 이 관측값을 모든 버전의 출력 규격으로 간주하지 않습니다.

프레임 검토에서 조준·발사·후속 반응의 순서는 참고할 수 있었지만, 활 상단이 잘리는 구간과 세부 형상 변화가 있어 정밀한 기하·그립의 기준으로는 채택하지 않았습니다. 기존 포즈의 조준·후속 반응 시간을 Blender에서 조정한 4초 클립을 추가했고, 최종 GLB의 원본 24개 클립과 모델 데이터가 동일하게 보존됐는지 확인했습니다.

최종 출력의 다각도·확대·시간 순서 프레임 검사에서 발견한 접촉 틈은 morph 범위가 내보내기 중 제한된 탓이었습니다. 원래 사용한 범위를 보존해 다시 내보내고 같은 조건으로 재검사했습니다. 이 사례의 시각 검사는 직접 연속 재생을 관찰한 것과 구분합니다. 한 동작의 타이밍 실험이며 어려운 동작 전반의 성공률, 모션 캡처 정확도, 모든 접촉의 물리적 타당성이나 다른 도구 대비 품질 우위를 검증한 것은 아닙니다. 참고의 핵심 자세·궤적·역동성을 재현했다는 근거로도 사용하지 않으며, 이는 위의 표현 비교로 별도 확인해야 합니다. 수정마다 새 영상을 생성할 필요는 없었습니다.
