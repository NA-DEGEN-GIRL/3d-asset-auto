# 3D assets

Use `scripts/assetctl.py` through this skill's resolved path; its wrapper locates the shared runtime even from another project. Run `doctor` to discover actual capabilities. Read [runtime.md](references/runtime.md) for commands and [specs.md](references/specs.md) when constructing requests. A submitted job or installed file is not evidence of successful inference.

## Choose the workflow

- Match the target project's existing scale, naming, materials and budgets. With no target, deliver portable GLB/source files without choosing an engine or creating an app.
- Before making or editing, define a few observable acceptance criteria for the request's core purpose and expected viewing/use conditions. Infer reasonable defaults and record assumptions. For functional work include representation, operating range, interactions and playback intent. Read [QUALITY.md](../../../docs/QUALITY.md) when appearance, interaction or motion determines acceptance; it guides targeted inspection, repair and optional `assess`. Choose criteria for this use, not a universal anatomy, topology or style checklist.
- For complex, unfamiliar or repeatedly failing motion, use [motion references](../../../docs/QUALITY.md#동작-참고-자료-활용) to clarify key poses and contact events before further authoring. Use inspected images/video or generate pose sheets when useful. Prepare needed sheets per clip with readable motion phases; a mixed-motion overview does not replace missing references for each clip. Check structural and panel consistency, adapt references to the target and compare actual poses. Generated images are not ground truth or delivery evidence; timing and transitions require temporal review.
- New meshes default to TRELLIS.2. Use a supplied reference or an available image-generation tool to prepare one; `prompt` is provenance, not text-to-image. Do not reconstruct the reference with Blender primitives or import a newly authored procedural mesh to bypass inference. New procedural geometry requires the user's explicit request. Existing supplied meshes can be imported and edited without regeneration.
- Choose editing independently of the mesh generator. Keep a static prop unrigged; use object keyframes for rigid motion, an existing rig when suitable, or SkinTokens as a learned rig draft when deformation needs one. Use local `blender-edit` for custom motion, rig/weight/material edits, and `merge-animations` for compatible clips. Read [BLENDER.md](../../../docs/BLENDER.md) at `<doctor.root>/docs/BLENDER.md` for authoring and merge contracts. A Tripo-generated mesh does not imply paid Tripo editing.
- Before complex motion on a new, changed or unverified rig, probe the required joint chains and skin deformation; reuse relevant evidence for unchanged inputs. Follow [staged diagnosis](../../../docs/QUALITY.md#리그와-동작의-단계별-진단) to locate failures in source motion, retargeting, skinning, attachments or export and correct the responsible stage. For organic deformation, choose weights, joint geometry or corrective shapes as needed for the intended range; separate flesh layers or muscle simulation are not universal requirements. This applies to authored and generated motion, including selected Kimodo work.
- `process` provides local SkinTokens rig drafts, procedural Blender IK `idle`/`walk`/`run`, and GeoSAM2 part masks. Read [CHARACTERS.md](../../../docs/CHARACTERS.md) at `<doctor.root>/docs/CHARACTERS.md` when needed; install only the relevant learned backend. Presets retain other clips and replace only the requested preset in a new revision. Custom scripts and presets are not captured or learned motion. Do not call hand-authored bones learned output or connectivity splits semantic segmentation.
- Use Kimodo only when the user explicitly selects it for learned humanoid motion; otherwise choose existing clips, Blender authoring or local presets to fit the task. A generic animation request, installed models or a failed edit does not select Kimodo or authorize its installation/inference. For a selected task, use `text-motion-plan` → `text-motion` without repeated confirmation; read [KIMODO.md](../../../docs/KIMODO.md) for setup, observed SOMA-to-target mapping and recovery. Do not replace requested Kimodo inference with procedural keyframes. Retargeting preserves existing clips but does not solve target contacts, detailed grips or seamless loops. Existing Kimodo clips can be edited in Blender without new inference.
- For segmentation, run `prepare-segment`, inspect its actual views, and author named positive/negative pixel points yourself. Do not turn this into an end-user annotation task. Preserve `unclassified` faces and inspect individual result parts. For unknown bone names, inspect joint positions/hierarchy and supply an observed `bone_map`; never infer anatomy from bone numbers alone.
- Choose Tripo only when the user explicitly asks for it. Read [TRIPO.md](../../../docs/TRIPO.md) at `<doctor.root>/docs/TRIPO.md` for paid input, cost and recovery rules. Key presence, missing local models or a failed inference never authorize switching to Tripo. Requested standard work proceeds without repeated credit approval; the optional estimate guard defaults to 100 and a smaller user limit wins.
- Static named `edit` uses actual object names and rejects rigged or animated parents; use `blender-edit` for these or broader changes. Import existing rigs with `asset_kind: "character"`, or object/morph animation without a rig with `asset_kind: "animated"`, both under `provider: "import"`. Author scripts for the requested local work; they execute trusted Python with full Blender/process access, not a sandbox or viewer API. Preserve existing clips by default; explicitly disable preservation only for intended changes to them. Merge matching rigs directly; use a deliberate Blender retarget script for differing rigs, not an assumed automatic solver.

- For several requested motions, follow [per-clip completion](../../../docs/QUALITY.md#여러-클립의-개별-완성): track references, criteria, review evidence and remaining work for every clip. Work through authoring, review and repair per clip or small related group; scale effort with the requested set instead of reducing each motion to fit a fixed task-wide image quota. Continue through all requested clips. Deliver one final GLB with all requested names unless separate files were requested; accumulate or merge compatible outputs and verify the final inventory and per-clip quality. Keep intermediate revisions as provenance.

## Execute and review

1. Prepare a validated spec, using absolute external file paths. Preserve source revisions. Submit long generation, preparation or editing work with `--async`; save the job ID and query `job`. Do not duplicate submissions while waiting.
2. For processing, use `process-plan` to check the exact source and required backend. For explicit Tripo, run the relevant plan and read-only balance internally, then continue within the requested scope. Do not expose keys or request another approval for the same authorized work.
3. Inspect numeric output and provenance. Keep the original mesh generator separate from `local_processing` or `remote_processing`; an imported/rendered file is not inference evidence. Character processing reports budget excess without automatically decimating its skin. Judge surface defects against intended appearance and construction; open boundaries and UV splits are not automatically errors to remove.
4. Inspect actual images of the final export at expected viewing scale. Use all five overview views for a new result or affected views for a narrow edit; add revealing close-ups when a critical feature or suspected defect remains unresolved. Judge interacting parts together, from their connected structure through contact and useful range; matching anchors alone does not establish good contact or function. Inspect segmentation parts individually.
5. For motion, inspect the same important states from complementary angles, including the opposite side when motion or contact is hidden; one camera or several views of a resting pose cannot approve the motion. Check transitions and, when timing matters, playback at the intended speed, including repeated cycles for loops. Default sample PNGs are a single-view overview. Optional `assess` renders front/side/back within a per-call image budget; select clips and split calls when coverage is insufficient. Read per-moment missing views and unassessed coverage. Apply loop rules only to loops and activity limits only when holds are unwanted. Record numeric, visual, functional and project evidence separately with `review`.
6. Record a defect, its failed criterion and diagnostic evidence, repair in a new revision, export again and recheck under the same revealing conditions. Check likely regressions and preservation of data outside the intended edit, including already reviewed clips affected by shared rig or weight changes. Plan repair effort for the number and complexity of requested clips and actual user constraints. Accept only with evidence for the relevant criteria; if the budget ends or progress stalls despite reconsidering the approach, preserve the best result and report incomplete work per clip. Numeric passes and "prototype" labels do not clear observed defects. Additional paid work must stay within existing authorization.

For incomplete child revisions use the matching resume command; an authored checkpoint avoids rerunning a script after a render failure. Local inference may restart if no reusable output exists. Tripo's unknown submission outcomes require reconciliation, never automatic POST retry.

## Choose only relevant integration checks

Blender renders support agent review without a browser. For standalone assets, deliver files and findings. For project integration, use that project's importer when compatibility needs checking. Godot is one optional adapter; it does not imply running Three.js too. Build/start a viewer only when an interactive preview or web rendering check was requested. The current viewer's static draw does not validate motion. Unperformed optional checks are untested, not generation failures.

## Report

Give the asset/revision, actual generation and processing backends, checks performed, material defects and usable GLB/source paths. Distinguish local readiness, model inference, numeric checks, visual review and engine tests. Mention a viewer URL only if requested and running. Keep models, references, logs and outputs local unless publication was requested; explicitly selected Tripo sends its input to that service.

When playback or functional assumptions matter, deliver the GLB-bound `usage.json` too. Preserve and reconcile clip policies/events through edits and merges; inherited intent is not inherited approval. Leave unsupported or unseen criteria explicitly untested.
